## Description

Populate `src/kanon_cli/completions/preamble.py` with the `PREAMBLE`
dict consumed by `shtab.complete(parser, shell, preamble=PREAMBLE)` in
E7-F1-S1-T1's handler. The dict has exactly two keys:

```python
PREAMBLE: dict[str, str] = {
    "bash": _BASH_PREAMBLE,
    "zsh":  _ZSH_PREAMBLE,
}
```

Each preamble defines the kanon-specific shell helper functions that
the generated completion script calls when the user tab-completes a
dynamic argument. The helpers shell out to
`kanon __complete_<name> "$cur"` (or `kanon __complete_<name> "$repo_url" "$cur"`
for `__complete_project_versions`), capture stdout line-by-line, and
hand the candidate list to `COMPREPLY` (bash) or `compadd` (zsh).

Helpers shipped in both bash and zsh preambles:

- `_kanon_complete_catalog_entries` -- shells out to
  `kanon __complete_catalog_entries "$cur"`.
- `_kanon_complete_source_names_in_kanon` -- shells out to
  `kanon __complete_source_names_in_kanon "$cur"`.
- `_kanon_complete_names_in_lockfile` -- shells out to
  `kanon __complete_names_in_lockfile "$cur"`.
- `_kanon_complete_catalog_versions` -- shells out to
  `kanon __complete_catalog_versions "$cur"`.
- `_kanon_complete_project_versions` -- shells out to
  `kanon __complete_project_versions "$repo_url" "$cur"`.
- `_kanon_complete_cached_catalogs` -- shells out to
  `kanon __complete_cached_catalogs "$cur"`.

The mid-token splitter helper (Section 11.5) lives in this same
preamble (`_kanon_complete_add_arg` in bash, the zsh equivalent in
zsh) and is the integration point E7-F2-S1-T7 wires through. T2 ships
an initial placeholder body for that helper (calls
`_kanon_complete_catalog_entries` unconditionally); T7 replaces the
body with the full `@`-splitting logic.

Every helper that shells out to `kanon __complete_*` checks
`${KANON_COMPLETION_ENABLED:-1}` BEFORE the subprocess call; when set
to `0`, the helper returns the empty candidate list immediately
without invoking kanon. Helpers respect `${KANON_COMPLETION_TIMEOUT:-2}`
by wrapping the subprocess call in `timeout`(1) where available; when
`timeout` is not on `PATH`, the helper falls back to the kanon
subprocess's own internal timeout (also bounded by
`KANON_COMPLETION_TIMEOUT`).

Spec source: spec Section 11.1 (preamble paragraph -- "PREAMBLE
defines kanon-specific shell functions for dynamic lookups"),
Section 11.3 (which `kanon __complete_*` subcommand each helper
shells out to), Section 11.4 (`KANON_COMPLETION_TIMEOUT`,
`KANON_COMPLETION_ENABLED` env vars the helpers honor), and
Section 11.5 (the mid-token splitter helper).
