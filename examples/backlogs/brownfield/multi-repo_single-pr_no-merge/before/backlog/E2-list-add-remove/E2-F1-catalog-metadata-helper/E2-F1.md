# E2-F1: `_parse_catalog_metadata()` shared helper

## Status: in-queue

## Description

Introduce the canonical reader for `<catalog-metadata>` blocks. Every new
command in this release (`kanon list`, `kanon add`, `kanon outdated`,
`kanon why`, `kanon catalog audit`, `kanon validate metadata`) reads
`*-marketplace.xml` files; without a single shared parser each command would
re-implement the same XML schema checks and drift.

The helper lives in a new module `src/kanon_cli/core/metadata.py` and
exports:

- `CatalogMetadata` dataclass with fields `name`, `display_name`,
  `description`, `version`, `type`, `owner_name`, `owner_email`, `keywords`.
- `_parse_catalog_metadata(xml_path: pathlib.Path) -> CatalogMetadata`.

Behaviour codifies soft-spot rule 1 (spec Section 3.5):

- Required fields: `name`, `display-name`, `description`, `version`. Missing
  any required field is a hard error naming the file path and the missing
  field.
- Recommended fields: `type`, `owner-name`, `owner-email`, `keywords`. Missing
  recommended fields emit a warning to stderr and the returned dataclass
  holds `None` (or empty list for `keywords`) in those slots.
- Duplicate child elements within the same `<catalog-metadata>` block raise
  a hard error naming the duplicated element.
- Multiple `<catalog-metadata>` blocks in one XML file raise a hard error.
- Malformed XML raises a hard error citing the file path and the parser
  error.

The function is a pure read; it never writes back to the XML file and never
mutates global state.

Spec source: spec Section 3.5 (soft-spot rule 1), spec Section 3 (existing
primitives table row 5 names this helper as the new extension target).
