# E9: `--help` snapshot tests (per command)

## Status: in-queue

## Description

Lock the verbatim `--help` output of every `kanon` subcommand behind
byte-for-byte snapshot tests. Spec Section 14 declares the help text as
contract: each command's `--help` lives in `tests/fixtures/help/` and is
asserted byte-for-byte against the captured stdout of the actual
`python -m kanon_cli <command> --help` invocation.

This epic ships:

- A single parametrised snapshot harness at
  `tests/functional/test_help_snapshots.py` that drives every command's
  `--help` through `subprocess.run` and diffs the captured stdout to the
  matching fixture file.
- One fixture file per command under `tests/fixtures/help/`:
  - `kanon-toplevel.txt` -- `kanon --help`
  - `kanon-list.txt` -- `kanon list --help`
  - `kanon-add.txt` -- `kanon add --help`
  - `kanon-remove.txt` -- `kanon remove --help`
  - `kanon-outdated.txt` -- `kanon outdated --help`
  - `kanon-why.txt` -- `kanon why --help`
  - `kanon-install.txt` -- `kanon install --help`
  - `kanon-doctor.txt` -- `kanon doctor --help`
  - `kanon-catalog.txt` -- `kanon catalog --help`
  - `kanon-catalog-audit.txt` -- `kanon catalog audit --help`
  - `kanon-completion.txt` -- `kanon completion --help`
  - `kanon-bootstrap.txt` -- `kanon bootstrap --help` (DEPRECATED prefix)

Snapshot tests are byte-compared. Any drift in argparse-rendered help
text (added flag, reworded description, reordered option group) fails
the test, so the contract is preserved deliberately rather than by
accident.

E9 is thin: per-command snapshot fixtures, no production code. Each
upstream command epic (E2-E7) lands the implementation; E9 freezes the
resulting help text against the spec's Section 14 reference.

Spec source:
- `spec/kanon-list-add-lock-features-spec.md` Section 14 (CLI `--help`
  reference, snapshot-tested) -- the full normative help-text contract.
- Section 14 also calls out the `kanon bootstrap --help` DEPRECATED
  prefix requirement, mirrored in `E6-F1-S1-T3`.
