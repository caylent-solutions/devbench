## Description

Implement the `__complete_project_versions` dynamic completer
(Section 11.3 row 5). New hidden subcommand
`kanon __complete_project_versions <repo-url> <current-token>` that:

1. Takes the `<repo-url>` as its FIRST positional argument (the
   project repo URL, not the manifest repo) and `<current-token>`
   as its second.
2. Canonicalizes the repo URL via `core/url.py::canonicalize_repo_url`
   (E1-F2-S1-T1) so different URL shapes (https vs ssh, with/without
   `.git`) hash to the same cache directory.
3. Reads through the cache from E7-F3 (`projects/<sha256-of-canonical-url>/tags.txt`).
4. On cache miss/stale, fetches via `git ls-remote --tags + --heads <repo-url>`,
   bounded by `KANON_COMPLETION_TIMEOUT`.
5. Applies the SAME PEP 440 tag-name filter as E7-F2-S1-T4 (imports
   `filter_pep440_tags` from `completions/pep440_filter.py`).
6. Deduplicates, prefix-filters by `<current-token>`, sorts, emits
   one ref per line.

Used by: the mid-token splitter helper (E7-F2-S1-T7) which routes
`kanon add foo@<TAB>` to this completer against the repo URL backing
the catalog entry named `foo`.

Failure handling identical to T1-T4. Additional failure path:
malformed / unparseable `<repo-url>` -> empty stdout + log entry
(`<ISO-8601> __complete_project_versions ValueError: <message>`).

Spec source: spec Section 11.3 row 5, Section 4.0 (URL
canonicalization), Section 0.4 (PEP 440 enforcement).
