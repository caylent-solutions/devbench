## Description

Add the `--refresh-lock-source <name>` flag to `kanon install`. When
present, the flag re-resolves exactly one top-level source's full chain
(the manifest XML at its current REVISION, all transitive `<include>`
references, and every `<project>` row) while preserving every other
top-level source's lockfile entries verbatim. Spec Section 4.7 contract:

- The `<name>` argument accepts either a source name (the key from
  `KANON_SOURCE_<name>_*` triples in `.kanon`) OR a catalog entry name
  (the human-readable name returned by `derive_source_name(<remote_url>,
  <xml_basename>)`). Both forms resolve to the same set of lockfile rows
  via `derive_source_name` (E2-F3-S1-T1).
- `--refresh-lock-source` requires a CLI-supplied or environment-supplied
  catalog source (same rule as `--refresh-lock`: the lockfile fallback
  is disabled on refresh paths).
- `--refresh-lock-source` is mutually exclusive with `--refresh-lock`
  (T2 added the group; this task adds the second member).
- Specifying a `<name>` that does not match any top-level source raises
  `UnknownSourceError` listing the known source names and the resolution
  attempts (`derive_source_name` outputs for catalog entries that did
  not match either).
- On successful refresh, the info-line is `"lockfile partially rebuilt:
  source <name> (M projects refreshed; K projects preserved)"`.

Implementation surface:

- Add `--refresh-lock-source <NAME>` to the argparse parser; the flag's
  value goes into the same `mutually_exclusive_group` T2 introduced.
- Pass through to `core/install.py::install` as new keyword argument
  `refresh_lock_source: str | None = None`.
- Add `InstallState.REFRESH_LOCK_SOURCE` enum value.
- New helper `_resolve_source_name(name: str, lockfile: Lockfile, kanon_sources:
  list[KanonSource]) -> SourceEntry` that:
  1. Tries `name` as a literal `KANON_SOURCE_<name>` key first.
  2. If no match, tries `name` as a catalog entry name via
     `derive_source_name`.
  3. If neither matches, raises `UnknownSourceError` with the diagnostic
     payload above.
- New helper `_refresh_one_source(source_entry, kanon_source, resolver) ->
  SourceEntry` that re-resolves the manifest XML chain (running
  `<include>` cycle/diamond detection from T6 if available; otherwise
  the existing in-T1 single-pass walker) and returns the rebuilt
  `SourceEntry`.
- New `_merge_partial_lockfile(old_lockfile, refreshed_source) -> Lockfile`
  that replaces exactly one `SourceEntry` in `old_lockfile.sources` and
  preserves the rest, plus the unchanged `[catalog]` block. The new
  `kanon_hash` is the freshly-computed value, NOT the old one (the
  `.kanon` content has been re-read on this path).

Spec source: `spec/kanon-list-add-lock-features-spec.md` Section 4.7 flags
table, `--refresh-lock-source` row.
