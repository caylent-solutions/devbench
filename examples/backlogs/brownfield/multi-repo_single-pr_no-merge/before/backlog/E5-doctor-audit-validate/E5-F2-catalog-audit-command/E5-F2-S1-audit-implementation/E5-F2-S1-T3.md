## Description

Implement the `source-name-derivation` check inside
`src/kanon_cli/commands/catalog.py` per spec Section 3.5 soft-spot rule 2.

The check function (`_check_source_name_derivation(target_path)`) walks
every `repo-specs/**/*-marketplace.xml` in the audit target. For each
file:

- Read `<catalog-metadata><name>` (the entry name).
- Compute the normalized source name via `derive_source_name(entry_name)`
  (E2-F3-S1-T1's helper). The normalization rule from soft-spot 2:
  "**always lowercase the input AND always replace `-` with `_`**". The
  helper is deterministic and one-way.
- WARN finding when the normalized form differs from the original entry
  name (e.g., `Foo-Bar` => `foo_bar`). The warning text names the XML
  path, the entry name, and the derived source name so the catalog
  author can decide whether to rename the entry to match the derived
  form.
- WARN finding when the entry name contains characters outside
  `[a-zA-Z0-9_-]`. The character set is legal but unusual; this warning
  helps authors spot accidental whitespace, dots, or non-ASCII.

Both findings are independent: an entry name may produce both warnings
(e.g., `Foo.Bar` -- contains `.` AND normalises to `foo.bar` which
differs from the original).

Register the check in the registry T1 created under name
`source-name-derivation`.

The character class for the "allowed entry-name charset" lives in
`constants.py` as `KANON_CATALOG_ENTRY_NAME_ALLOWED_CHARS_RE` (a
compiled regex) so the rule is testable data, not inline.

Source-test atomicity: this task modifies `catalog.py` (existing after
T1) and adds new tests. Fixture: `tests/fixtures/catalog/broken-soft-spot-2/`
with entries demonstrating each warning class.

Spec source: spec Section 3.5 soft-spot rule 2; Section 4.8 (`--check
source-name-derivation`); Section 1.1 terminology entry for "source name"
(deterministic normalisation).
