# E5-F2: `kanon catalog audit` catalog-author / consumer-side audit

## Status: in-queue

## Description

Add the `kanon catalog` subcommand group with `audit` as its first
sub-subcommand. Creates `src/kanon_cli/commands/catalog.py` and registers
the subcommand under `cli.py`. The audit command runs the five soft-spot
checks from Section 3.5 plus a legacy-directory deprecation warning, against
either:

- A local directory (default arg `.`, the current directory which must be a
  manifest-repo root), OR
- A `<git_url>@<ref>` catalog source (clones to cache, audits there).

`--check` accepts a comma-separated subset (`--check metadata,tag-format`)
or the single value `all` (default). Valid subset names:

- `metadata` (soft-spot 1) -- required + recommended `<catalog-metadata>`
  fields, duplicate-child detection, multiple-`<catalog-metadata>` detection.
- `source-name-derivation` (soft-spot 2) -- warns when the entry name
  normalises to a different source name and when the entry name contains
  characters outside `[a-zA-Z0-9_-]`.
- `entry-name-uniqueness` (soft-spot 3) -- collisions across XML files
  in the same manifest repo are errors, naming every offending XML path.
- `remote-url` (soft-spot 4) -- resolves every `<project remote="X">`
  to a concrete fetch URL by walking `<include>` chains. Errors when
  unresolvable. Also checks the HTTPS-by-default policy (Section 3.6;
  `KANON_ALLOW_INSECURE_REMOTES=1` opts out).
- `tag-format` (soft-spot 5; PEP 440) -- warns about tags whose last
  path component is not a valid PEP 440 version. Warning-only (not error)
  so manifest repos with legitimate non-version tags (ops markers,
  release-prep tags) still work. Reads tags via `git ls-remote --tags`.

Additional behaviours:

- Empty subset list, invalid subset name, or `all` mixed with any other
  subset (e.g., `--check all,metadata`) is a hard error at argparse time.
- Detection of a legacy `catalog/<name>/` directory tree in the manifest
  repo emits a warning per Section 4.8 ("Legacy catalog/ directory
  detected; this directory is unused by kanon >= <this-version> and should
  be deleted; see docs/migration-bootstrap-to-add.md"). Warning-only during
  the deprecation window.
- `--strict` promotes every warning to an error (exit non-zero on any
  warning).

The work decomposes into a single story (E5-F2-S1) with eight tasks:
T1 lays the framework and the `--check` parser, T2-T6 implement each
soft-spot in turn, T7 adds the legacy-directory check, and T8 adds the
`--strict` flag.

Spec source: spec Section 3.5 (soft-spot rules) and Section 4.8 (`kanon
catalog audit`) and Section 3.6 (HTTPS-by-default).
