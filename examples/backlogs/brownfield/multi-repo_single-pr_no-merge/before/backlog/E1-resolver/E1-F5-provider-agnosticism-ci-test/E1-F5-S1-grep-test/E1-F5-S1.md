## Description

One Task (T1): author the CI test
`tests/functional/test_provider_agnostic.py`, create the empty
allowlist file `tests/integration/provider_allowlist.txt`, and update
the two affected docs (`docs/security-model.md`,
`docs/contributing.md`) to reference the test and allowlist.

The test enumerates tracked files via `subprocess.check_output(["git",
"ls-files"])`, filters out the allowlist set (built from
`docs/`, `tests/fixtures/`, `.git/`, plus any path enumerated in
`tests/integration/provider_allowlist.txt`), and scans each remaining
file for the forbidden CLI and hostname tokens. On match, the assertion
names the file, line number, and matched token plus the remediation.

Source/test atomicity does not apply here in the usual `src/`-paired
sense: this is itself a test module with no production-code counterpart.
The Task ships the test plus its allowlist plus the docs update in one
work unit.

Spec source: `spec/kanon-list-add-lock-features-spec.md` Section 10
line 1023; Section 12 acceptance item 20.
