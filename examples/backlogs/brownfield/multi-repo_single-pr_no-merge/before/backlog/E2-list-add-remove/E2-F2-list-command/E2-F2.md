# E2-F2: `kanon list` command

## Status: in-queue

## Description

Implement the new top-level `kanon list` subcommand and all of its flags as
specified in spec Section 4.1. The command walks `repo-specs/**/*-marketplace.xml`
inside the resolved manifest repo, parses each `<catalog-metadata>` block via
the shared helper from E2-F1, and emits the catalog entries in one of several
formats.

The feature ships as six sequential tasks in a single story so the command
file grows incrementally and the integration suite covers each flag as it
lands:

- **T1** introduces the command itself plus the default `<entry-name>` output
  and the empty-catalog handling. It also registers the new subcommand on the
  top-level argparse in `src/kanon_cli/cli.py`.
- **T2** adds `--detail`.
- **T3** adds `--tree`, `--max-depth N`, `--no-filter-required`, the
  threshold guardrail (`KANON_TREE_NO_FILTER_THRESHOLD`), and the
  `--tree` + `--all-versions` mutual-exclusion check.
- **T4** adds `--all-versions`, `--limit N`, `--no-limit`,
  `--since-version <spec>`, and the `KANON_LIST_LIMIT` cap.
- **T5** adds `--format {names,json}` (with `KANON_LIST_FORMAT`).
- **T6** adds the filter framework: positional `<substring>`, `--regex`,
  `--match-fields <csv>`, the "match-fields without filter" hard error,
  and the zero-match stderr note.

Each task ships its own unit and integration tests. The integration tests
build a temporary fixture manifest repo (a local `file://` clone with
synthesized `repo-specs/**/*-marketplace.xml` files) and invoke
`kanon list --catalog-source <file>@<ref>` via subprocess; per spec Section 3.6
`file://` URLs are allowed when `KANON_ALLOW_INSECURE_REMOTES=1` is set.

Spec source: spec Section 4.1.
