## Description

Extend the `kanon add` command (introduced by E2-F4-S1-T1) with three
features per spec Section 4.2:

1. `--dry-run`: prints the diff that WOULD be written to the destination
   `.kanon` file, makes no on-disk change, and exits 0.
2. `--force`: overrides the collision detection so an existing source-name
   block in the destination file is overwritten by the new block.
3. Collision detection pre-flight:
   - **Within the requested set.** If `kanon add a a` (same name twice) or
     two requested entries normalise to the same source name (e.g.,
     `kanon add foo-bar Foo-Bar`), hard error before any write.
   - **Against existing blocks in the destination file.** For each
     requested source name, scan the destination `.kanon` for an existing
     `KANON_SOURCE_<source_name>_*` triple. Any collision without
     `--force` is a hard error with the spec-canonical message:
     ```
     source-name 'foo' already mapped to <existing-url>/<existing-path>
     (revision <existing-spec>); requested mapping is
     <new-url>/<new-path> (revision <new-spec>).
     Use --force to overwrite, or 'kanon remove foo' first.
     ```

`--dry-run` diff format:

- Uses unified-diff-like rendering with `+` for added lines and `-` for
  lines that would be removed (under `--force`). For the common case
  (collision-free add), every line is a `+`.
- Diff target lines are read from the same in-memory buffer produced by
  the triple-writer (E2-F4-S1-T1 refactored the writer to share the
  buffer with `--dry-run`).

`--force` semantics:

- Replaces the three matching `KANON_SOURCE_<source_name>_{URL,REVISION,PATH}`
  lines wherever they appear in the file, preserving the line order of
  remaining content. (The same line-preservation rules used by `kanon
  remove` apply; see E2-F5-S1-T2.)
- The dry-run rendering for a `--force` overwrite shows the three removed
  lines (with `-` prefix) and the three replacement lines (with `+`
  prefix).
