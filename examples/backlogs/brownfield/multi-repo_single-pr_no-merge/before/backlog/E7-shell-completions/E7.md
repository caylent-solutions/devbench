# E7: Shell completions (bash + zsh, 100% coverage)

## Status: in-queue

## Description

Ships full tab-completion support for `kanon` in bash and zsh. Every
command, every positional, and every flag listed in spec Section 11.2
is tab-completable. Static surfaces (subcommand names, enum-valued
flags, filesystem paths) are emitted from `argparse` introspection
via `shtab`; dynamic surfaces (catalog entry names, source names from
the local `.kanon`, lockfile names, PEP 440-valid git tags + branches,
cached catalog `<url>@<ref>` pairs) are emitted by hidden
`kanon __complete_*` subcommands that the preamble shell helpers invoke
at tab-press time.

Net-new infrastructure shipped by this epic:

- A new `kanon completion <shell>` top-level subcommand (Section 11.1)
  that emits the completion script to stdout. Two install paths
  documented: `eval "$(kanon completion bash)"` (auto-updating) and
  `kanon completion bash > <static-file>` (faster startup).
- A `PREAMBLE` dict (bash + zsh shell helper functions) that the
  generated script embeds. The preamble shells out to
  `kanon __complete_<name>` and feeds stdout to the shell as
  completion candidates.
- Six dynamic completers (Section 11.3 table): `__complete_catalog_entries`,
  `__complete_source_names_in_kanon`, `__complete_names_in_lockfile`,
  `__complete_catalog_versions`, `__complete_project_versions <repo-url>`,
  `__complete_cached_catalogs`. Each is failure-quiet on stdout
  (empty list on error) and failure-loud on stderr (structured entry
  to `${KANON_CACHE_DIR}/completion-errors.log`).
- A mid-token splitter (Section 11.5) so `kanon add foo@<TAB>` routes
  to `__complete_project_versions` against the repo URL backing the
  catalog entry named to the left of the last `@`. Without `@`, routes
  to `__complete_catalog_entries`.
- A TTL-cached local mirror (Section 11.4) so a warm tab-press has
  no network round-trip. Cache layout, directory mode `0700`, file
  mode `0600`, clock-skew handling, `accessed_at` coalescing
  (configurable via `KANON_ACCESSED_AT_COALESCE_SEC`), background
  refresh on stale, output sanitization (drop entries with newlines,
  NULs, or shell metacharacters).
- Integration tests under bash + zsh (Section 11.8) that exercise
  every row of the Section 11.2 matrix via `compgen -F` (bash) and
  `_main_complete` (zsh). Snapshot tests on the generated scripts so
  static-surface drift fails CI; refresh workflow via
  `make update-completion-snapshots`.

Spec source: `spec/kanon-list-add-lock-features-spec.md` Section 11
(all subsections 11.1 through 11.9).

E7 depends on E2 (list / add / remove must exist for completers to
suggest from), E3 (lockfile must exist for `__complete_names_in_lockfile`),
and E1 (widened bare PEP 440 sets the parsing baseline for the
`__complete_catalog_versions` / `__complete_project_versions` filters).
