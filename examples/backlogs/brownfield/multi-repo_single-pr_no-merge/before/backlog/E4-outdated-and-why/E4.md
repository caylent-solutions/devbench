# E4: `kanon outdated` + `kanon why`

## Status: in-queue

## Description

Two read-only inspection commands that consume the catalog + `.kanon` + (optionally) `.kanon.lock`
to answer the two operator questions every dependency manager must answer:

- **`kanon outdated`** (spec Section 4.4) -- report installable upgrades per source. One row per
  `KANON_SOURCE_<name>_*` block: current resolved version, latest version matching the spec, latest
  available version ignoring the spec, and an upgrade-type column. Default exit 0 regardless of
  upgrade availability (spec Section 0.2); `--fail-on-upgrade` opts in to non-zero exit for CI
  gating. Branch-pinned sources display branch HEAD SHA (12-char truncated) in the version columns
  and report `drift` in the upgrade-type column when the locked SHA differs from the branch HEAD.
  Supports `--format table` (default) and `--format json`.
- **`kanon why <name-or-url>`** (spec Section 4.5) -- explain why a transitive package or source is
  in the resolved tree. Resolves the full tree from `.kanon.lock` when present, otherwise live-
  resolves against the catalog. Argument matching has three precedence categories
  (`<project>` URL via `canonicalize_repo_url`, transitive XML manifest path, top-level source name
  via `derive_source_name`); ambiguity across categories is a hard error listing both
  interpretations. For every chain in the tree ending at the requested node, prints
  `<top-level-source> -> <xml-manifest-path>@<resolved-sha> -> ... -> <project>@<resolved-sha>`.
  Supports `--format text` (default) and `--format json`. Not-found errors include a Levenshtein-
  distance-bounded closest-match suggestion.

Both commands depend on:

- **E1** for the resolver, `canonicalize_repo_url`, and the shared `--catalog-source` /
  `--kanon-file` / `--lock-file` flag definitions in `core/cli_args.py`.
- **E2** for `parse_catalog_metadata` and `derive_source_name`.
- **E3** for the lockfile reader (consumed by both commands when `.kanon.lock` is present) and the
  `kanon_hash` consistency check.

Spec source: `spec/kanon-list-add-lock-features-spec.md` Sections 4.4 (`outdated`), 4.5 (`why`),
0.2 (`outdated` exit-code policy), and 7 (flag / env-var tables, including `KANON_OUTDATED_FORMAT`
and `KANON_WHY_FORMAT` defaults).
