# E5-F1: `kanon doctor` workspace health check

## Status: in-queue

## Description

Add the `kanon doctor` command (new `commands/doctor.py`, registered in
`cli.py`). The command is workspace-oriented: every check operates on the
operator's `.kanon` + `.kanon.lock` files and on the operator's cache
directory, never on a remote catalog (those checks live in
`kanon catalog audit`, E5-F2).

Doctor's eleven subchecks, per spec Section 4.6:

1. Cross-check `.kanon` + `.kanon.lock` consistency via `kanon_hash`.
   `.kanon` absent => hard error. `.kanon.lock` absent => info-level notice;
   skip checks 2-5 and 11; still run checks 6-10.
2. Hand-edit detection (`kanon_hash` mismatch) -> error.
3. Orphaned lock entries (source removed from `.kanon` but still in lock)
   -> error.
4. Branch drift (lockfile SHA != branch tip). Info-notice by default;
   `--strict-drift` promotes to error.
5. Dangling SHA -- every locked SHA still reachable via
   `git ls-remote --exit-code <url> <sha>`; error on dangling.
6. Effective catalog source resolution (CLI flag > env var > lockfile
   `[catalog].source` > none). Print the resolved value so the operator
   spots shell-profile leakage.
7. Report the N most recent completion errors from
   `${KANON_CACHE_DIR}/completion-errors.log` (default N=5).
8. `--refresh-completion-cache` flag: invalidate the completion cache
   before any other checks; useful escape hatch when the cache is corrupt.
9. Completion-script staleness: when a static completion script is
   installed, compare its on-disk hash to a fresh `kanon completion <shell>`
   invocation; warn on drift.
10. `--prune-cache` flag: prune `${KANON_CACHE_DIR}` entries that have
    not been accessed within `KANON_CACHE_PRUNE_AGE_DAYS` days (default 30).
    Also reports stale `.kanon-data/.kanon-install.lock` files held by no
    live process (advisory only; `fcntl.flock` self-cleans on exit).
11. Remote reachability sanity check (runs only when `.kanon.lock`
    present). For every distinct `<remote>` URL in the lockfile, run
    `git ls-remote --exit-code <url> HEAD` (subject to
    `KANON_RESOLVE_TIMEOUT` and the existing retry policy). Errors are
    reported but do NOT fail the doctor command (network is transient);
    they help catch missing SSH keys / unconfigured credential helpers.

The work is decomposed into a single story (E5-F1-S1) and five tasks
that split the eleven subchecks into atomic source/test pairs.

Spec source: spec Section 4.6 (workspace health check) and Section 3.6
(trust model -- the effective-source print is the key audit surface).
