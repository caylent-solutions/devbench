# E7-F3-S1: Cache implementation (layout, TTL, coalescing, sanitization, refresh)

## Status: in-queue

## Description

Story scope: ship `src/kanon_cli/completions/cache.py` end-to-end, plus
`src/kanon_cli/completions/sanitize.py`. Five tasks in this order:

- **T1** -- cache layout + file I/O + `0700`/`0600` permission helpers;
  populates `src/kanon_cli/constants.py` with every env var name and
  default value the cache needs.
- **T2** -- TTL math + clock-skew handling. Depends on T1 for the
  layout helpers.
- **T3** -- `accessed_at` coalescing. Depends on T1 for the file I/O
  helpers.
- **T4** -- output sanitization (newline / NUL / shell metacharacter
  filter). Depends on T1 because the sanitizer is invoked from
  `cache.write_entries()`.
- **T5** -- background refresh on stale. Depends on T2 because the
  refresh trigger is the staleness check itself.

Each task writes both production source and matching unit tests in the
same Manifest per source-test atomicity.

Spec source: spec Section 11.4 (cache layout + lifecycle), 11.3
("Output sanitization" paragraph), 3.6 (trust model -- "Cache files
are user-private", "Completion candidates are shell-escaped").
