## Description

Extend `src/kanon_cli/core/metadata.py` (introduced by E2-F1-S1-T1) with
`derive_source_name(entry_name: str) -> str` and add the matching tests
to `tests/unit/test_derive_source_name.py`.

The rule is unconditional (spec Section 3.5 soft-spot rule 2):

1. Lowercase the input.
2. Replace every `-` with `_`.

No other transformation is applied. The function is deterministic, pure,
and idempotent (`derive_source_name(derive_source_name(x))` equals
`derive_source_name(x)` for every legal input).

Author-awareness warning:

- If the input contains any character outside the set `[a-zA-Z0-9_-]`
  (still legal under the soft-spot rule, but discouraged), the helper
  emits a single-line warning to stderr noting that the entry name
  contains characters outside the recommended set and the normalised form
  may not survive shell quoting cleanly. The warning is emitted at most
  once per input value (a process-level dedupe cache is fine, but not
  required for this task; the simplest implementation just warns on every
  call).

Signature and behaviour:

```
def derive_source_name(entry_name: str) -> str:
    """Normalise <catalog-metadata><name> to a KANON_SOURCE_<name>_* token."""
```

The function does NOT validate the entry-name shape beyond emitting the
character-set warning; it transforms whatever string the caller passes.
Empty strings produce empty strings (legal input shape is the caller's
responsibility, not this helper's).
