## Description

Implement the `__complete_source_names_in_kanon` dynamic completer
(Section 11.3 row 2). New hidden subcommand
`kanon __complete_source_names_in_kanon <current-token>` that:

1. Resolves the path to the active `.kanon` file from
   `${KANON_KANON_FILE:-./.kanon}` (the env-var precedence ladder
   already implemented in `core/config.py`; reuse it -- do not
   reimplement).
2. Parses every `KANON_SOURCE_<name>_URL` key in the `.kanon` file
   (the existing parser in `core/kanon_file.py` is the canonical
   reader -- reuse).
3. Emits one normalized source name per line. Normalization is one-way
   and lossy: the original entry name CANNOT be reconstructed from
   the source name and is NOT emitted. The normalized form is what
   already lives in the `<name>` portion of the `KANON_SOURCE_<name>_URL`
   key, so no derivation step is needed at completion time.
4. Filters by prefix-match against `<current-token>`; emits results
   line-by-line.

Failure handling follows the same contract as E7-F2-S1-T1: empty
stdout on error, structured log line to
`${KANON_CACHE_DIR}/completion-errors.log`,
`KANON_COMPLETION_ENABLED=0` short-circuit.

Documented one-way-and-lossy contract: the spec is explicit (Section
11.3 row 2) that operators who remember the entry name can type it
at the command line and `derive_source_name()` will normalize it at
command time; tab-completion is suggest-only.

Used by: `kanon remove <name>`, `kanon install --refresh-lock-source <name>`,
and `kanon why <name>` (resolved against lockfile in a separate
completer). The shell helper invoking this is
`_kanon_complete_source_names_in_kanon` from E7-F1-S1-T2's PREAMBLE.

Registration: `cli.py` UPDATE -- hidden subcommand with
`help=argparse.SUPPRESS`.

Spec source: spec Section 11.3 row 2 (with normalization-is-lossy
note), Section 11.4 cache lifecycle is N/A here (no network).
