# E3-F1-S1: TOML lockfile parser, writer, and schema migration

## Status: in-queue

## Description

Ship the lockfile reader, writer, and migration policy in a single module
under `src/kanon_cli/core/lockfile.py`. Story scope:

1. T1 introduces the `Lockfile` dataclass tree (top-level fields, `[catalog]`
   block, `[[sources]]` array, nested `[[sources.includes]]`, and
   `[[sources.projects]]` rows), the parser, and the atomic writer.
2. T2 layers the schema migration policy on top of T1: forward-incompatible
   schema reads raise a structured error; backward-compatible reads dispatch
   to per-version upgraders (only v1 is shipped now, so the upgrader registry
   is empty but the dispatch infrastructure exists for future v2).

The two tasks land in this order because T2 wraps T1's `read_lockfile` entry
point. T2 reuses T1's dataclass tree and validation; the only new code in T2
is the schema_version detection and the upgrader registry.

Spec source: `spec/kanon-list-add-lock-features-spec.md` Section 5 (schema)
and Section 5.2 (migration policy).
