# E3-F3-S1-T7: Default `--lock-file` derivation from `--kanon-file`

## Description

Implement the spec Section 4.7 "Default --lock-file derivation" rule:

> When `--kanon-file` is the default (`./.kanon`), `--lock-file` defaults
> to `./.kanon.lock`. When `--kanon-file` is set to a non-default path
> (CLI flag or `KANON_KANON_FILE` env var), `--lock-file` defaults to
> `<kanon-file-path>.lock`. Operators running parallel installs in the
> same directory with different `--kanon-file` values therefore get
> distinct lockfile paths by default; explicit `--lock-file` always
> wins. `KANON_LOCK_FILE` env var, when set, also wins over the
> derivation.

The precedence chain is:

1. Explicit `--lock-file <path>` CLI flag.
2. `KANON_LOCK_FILE` env var.
3. `<kanon-file-path>.lock` (the derivation).

This rule applies to every command that takes `--lock-file`:
`kanon install`, `kanon doctor` (E5), `kanon outdated` (E4), `kanon why`
(E4). This task wires the derivation helper in a shared module so all
four commands consume the same logic; in this task only the `install`
wiring is shipped, with explicit "TODO: wire E4 and E5 in their own
tasks" comments (no, that violates fail-fast and no-TODOs; the helper
ships standalone and each downstream command's task wires it without
needing changes here).

Implementation surface:

- Add `derive_lock_file_path(kanon_file_path: Path, cli_lock_file: Path |
  None, env_lock_file: str | None) -> Path` helper in
  `src/kanon_cli/utils/lock_file_path.py` (new module). Logic:
  1. If `cli_lock_file is not None`, return `cli_lock_file`.
  2. If `env_lock_file is not None and env_lock_file != ""`, return
     `Path(env_lock_file)`.
  3. Return `kanon_file_path.with_suffix(kanon_file_path.suffix + ".lock")`
     using path string manipulation; for the default `./.kanon`, this
     produces `./.kanon.lock`.
- Add a parametrised `--lock-file PATH` argparse flag to
  `src/kanon_cli/commands/install.py` (the flag was implicitly present
  for T1 to consume, but T1 left the resolution at the call-site; T7
  formalises it and adds the env-var read).
- Add the env-var read of `KANON_LOCK_FILE` from `constants.py` (the
  constant was added by E3-F1-S1-T1) and pass it to
  `derive_lock_file_path`.
- Update `src/kanon_cli/core/install.py::install` to receive the
  pre-resolved `lock_file_path: Path` (no longer optional); the
  command-handler layer is responsible for resolution.

Spec source: `spec/kanon-list-add-lock-features-spec.md` Section 4.7
"Default --lock-file derivation" paragraph; Section 4.7 flags-table row
for `--lock-file`.
