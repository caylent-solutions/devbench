## Description

Implement the `__complete_names_in_lockfile` dynamic completer
(Section 11.3 row 3). New hidden subcommand
`kanon __complete_names_in_lockfile <current-token>` that:

1. Resolves the lockfile path per spec Section 4.7: explicit
   `--lock-file <path>`, then `${KANON_LOCK_FILE}`, then
   `<kanon-file>.lock`, then `.kanon.lock` in CWD. The resolution
   helper already exists in `core/lockfile.py` (E3-F1-S1-T1) -- reuse.
2. Reads the lockfile (XML per Section 5). Enumerates:
   - every top-level `<source name="...">` element's `name` attr,
   - every transitive `<include path="...">` element's `path` attr
     (recursive through nested `<source>` children),
   - every `<project repo-url="...">` element's `repo-url` attr.
3. Deduplicates, filters by prefix-match against `<current-token>`,
   emits one name per line, sorted deterministically.

Failure handling identical to T1/T2: empty stdout on error,
structured log line, `KANON_COMPLETION_ENABLED=0` short-circuit.

Used by: `kanon why <name-or-url>`. The shell helper invoking this
is `_kanon_complete_names_in_lockfile` from E7-F1-S1-T2's PREAMBLE.

Spec source: spec Section 11.3 row 3, Section 4.7 (lockfile path
resolution), Section 5 (lockfile XML format).
