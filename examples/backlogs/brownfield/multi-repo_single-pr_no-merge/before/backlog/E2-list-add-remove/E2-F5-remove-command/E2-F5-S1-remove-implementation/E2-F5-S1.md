# E2-F5-S1: `kanon remove` implementation across core and write-rules

## Status: in-queue

## Description

Single-story decomposition of the `kanon remove` implementation. Two
tasks in strict sequence (T1 -> T2):

- **T1** Core remove path: argparse subparser, source-name normalisation
  via `derive_source_name`, scan-and-strip of the three matching
  `KANON_SOURCE_<normalized>_{URL,REVISION,PATH}` lines, the
  fewer-than-three-keys hard error.
- **T2** `--dry-run` plus the file-writing rules (line-ending sniff,
  blank-run collapse, trailing-newline normalisation).

Spec source: spec Section 4.3.
