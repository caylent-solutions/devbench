# E4-F1: `kanon outdated` command

## Status: in-queue

## Description

Implement `kanon outdated` (spec Section 4.4) as a new subcommand under `src/kanon_cli/commands/`.
The command resolves the catalog (required; no lockfile fallback for this command per spec Section
4.4 behaviour 1), reads `.kanon`, and for each `KANON_SOURCE_<name>_*` block computes three
columns:

- **current** -- resolved version from `.kanon.lock` if present, otherwise live-resolved against
  the catalog.
- **latest-matching-spec** -- the latest version under the source's prefix that satisfies the
  spec, via `version.py::_resolve_constraint_from_tags`. Zero PEP 440-parseable tags under the
  prefix raises a loud error per soft-spot 5 (delegated to E1-F1-S1-T2's loud-error helper).
- **latest-available** -- the latest version ignoring the spec (the upgrade the operator could
  reach if they relaxed the spec).

Output is one row per source: `name | current | latest-matching-spec | latest-available |
upgrade-type`. Default format `table`; `--format json` mirrors the table with one object per
source. Default exit code 0 regardless of upgrade availability (spec Section 0.2); `--fail-on-
upgrade` opts in to exit 1 when any source has an available upgrade (CI gating).

For sources whose REVISION is a branch name (e.g., `main`, `develop`), both `latest-matching-spec`
and `latest-available` display the branch HEAD SHA truncated to 12 characters; `upgrade-type`
reports `drift` when the locked SHA differs from the branch HEAD. There is no "latest available
across all branches" notion in the spec.

The feature decomposes into one story (`E4-F1-S1`) with four sequential tasks:

- **T1** -- Core tag-based outdated implementation (registers the subcommand, default `table`
  format, three-column row construction for tag-pinned sources).
- **T2** -- Branch-pinned source columns (HEAD-SHA truncation + `drift` upgrade-type detection).
- **T3** -- `--fail-on-upgrade` exit-code flag.
- **T4** -- `--format json` output.

Spec source: `spec/kanon-list-add-lock-features-spec.md` Section 4.4 and Section 0.2.
