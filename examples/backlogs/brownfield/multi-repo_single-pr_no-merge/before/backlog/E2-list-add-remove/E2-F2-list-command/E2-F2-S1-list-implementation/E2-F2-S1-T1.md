## Description

Introduce the new top-level `kanon list` subcommand. This task lands the
command shell, the default output mode (one entry name per line, pipeable
into `kanon add`), the empty-catalog handling, and the registration on the
top-level argparse parser in `src/kanon_cli/cli.py`. Every later task in
this story extends the same module.

New command module `src/kanon_cli/commands/list.py`:

- Argparse subparser `list` that imports the `--catalog-source` argument
  factory from `src/kanon_cli/core/cli_args.py` (introduced by
  E1-F4-S1-T1). Wires `KANON_CATALOG_SOURCE` env-var precedence per spec
  Section 4 header.
- Adds the `--no-color` flag at this task's scope (the flag is shared by
  every later task; T5 also reads `KANON_LIST_FORMAT`).
- Entry-point function (e.g., `run_list(args) -> int`) that:
  1. Resolves the catalog source via the shared resolver
     (`resolve_catalog_dir()` from `src/kanon_cli/core/catalog.py`). If
     neither flag nor env var is set, exits with the canonical
     missing-catalog error from spec Section 4 header (verbatim string).
  2. Walks `repo-specs/**/*-marketplace.xml` inside the resolved manifest
     repo using `pathlib.Path.rglob`. Skips the legacy `catalog/<name>/`
     directory if present (the spec explicitly says `kanon list` reads
     ONLY the XML manifests in `repo-specs/`).
  3. For each XML file, calls `_parse_catalog_metadata()` from
     `src/kanon_cli/core/metadata.py` (E2-F1-S1-T1). Collects the entry
     names.
  4. Builds the entry-name index sorted lexicographically (stable across
     runs).
  5. If the index is empty: exits 0 with empty stdout and writes
     `manifest repo contains 0 entries` (or the equivalent canonical
     phrase) as a single line to stderr.
  6. Otherwise, prints one entry name per line to stdout. Streams output
     (no full-result buffering) per spec Section 4.1 "Streaming".

`src/kanon_cli/cli.py` change:

- Register the new `list` subcommand on the top-level argparse parser so
  `kanon list --help` works. The hook follows the existing pattern used
  for `bootstrap`, `clean`, `install`, `repo`, `validate`.

2. **NO SILENT FAILURES** -- Every error must produce a clear, actionable error message sent to stderr. Every error must result in a non-zero exit code. Never swallow exceptions. Never log-and-continue when the operation was required to succeed.
3. **FAIL FAST** -- Detect errors at the earliest possible point. Validate inputs before processing. Check prerequisites before starting work. Exit immediately on the first error with a message that tells the user exactly what went wrong and what to do about it.
4. **NO HARD-CODED VALUES** -- No URLs, paths, timeouts, retry counts, port numbers, hostnames, credentials, feature flags, or environment-specific values in source code. All constants live in `src/kanon_cli/constants.py`, never inline in source files. All configuration comes from environment variables, configuration files, or function parameters.

The existing `KANON_GIT_RETRY_DELAY` (wait between known-failed `git ls-remote` retries) is the ONLY allowed sleep-based wait in this codebase. Use readiness detection, event-driven callbacks, or polling with configurable timeouts everywhere else.
6. **ALL CODE MUST BE DYNAMIC AND INPUT-DRIVEN** -- No static data, no hard-coded test fixtures embedded in source, no magic numbers. All thresholds, limits, paths, and identifiers must be parameterized.
