# E1-F3: `@` splitter coverage hardening for `_parse_catalog_source`

## Status: in-queue

## Description

Test-only hardening for the existing `_parse_catalog_source` helper in
`src/kanon_cli/core/catalog.py`. The split-on-LAST-`@` logic at line 67
already implements spec Section 4.0's "`@` separator parsing" rule
correctly today; this feature adds the test coverage that proves it
covers the SSH-URL-with-`@`-in-user-info cases.

Test cases to add:

- `git@host:org/repo.git@main` -- correct split into
  `(git@host:org/repo.git, main)`.
- `https://user@host.com/repo.git@==1.0.0` -- multi-`@` with user-info
  and a PEP 440 constraint.
- `git@host:org/repo.git` -- no ref -> expects `ValueError`.
- `@main` -- empty URL -> expects `ValueError`.
- `https://h/r.git@` -- empty ref -> expects `ValueError`.

Production code is unchanged. This is a pure test-coverage hardening
feature.

Spec source: `spec/kanon-list-add-lock-features-spec.md` Section 4.0
"`@` separator parsing" subsection and Section 3 primitives table row 4
(`_parse_catalog_source`).
