# E10-F2-S1: CI workflow + guards (three GitHub Actions workflows)

## Status: in-queue

## Description

Three independent GitHub Actions workflows enforce spec Section 9a's CI
bullets 1-5 in the `caylent/caylent-private-kanon` repo. The workflows
are file-disjoint (`.github/workflows/audit.yml`,
`.github/workflows/no-catalog-dir.yml`,
`.github/workflows/pep440-tags.yml`) so the three tasks can be executed
in parallel by the autonomous loop. All three are YAML-tier (no Python
source authored; small inline `python -c "..."` snippets are permitted
in T3 for PEP 440 validation but produce no `.py` files in the
Manifest).

Task list:

- **T1 -- `audit.yml`.** PR + push-to-main triggers. Runs `kanon catalog
  audit .`, the three `kanon validate` sub-subcommands, and the `kanon
  list` smoke test that compares CLI-returned entries against `git
  ls-files repo-specs/**/*-marketplace.xml`.
- **T2 -- `no-catalog-dir.yml`.** PR trigger. Fails on any new path
  matching `^catalog/[^/]+/` introduced by the PR diff against
  `origin/main`.
- **T3 -- `pep440-tags.yml`.** Tag-push + PR trigger. Validates the
  last-path-component of every new tag against PEP 440. Warning-only
  initially per spec Section 15.

Spec source: `spec/kanon-list-add-lock-features-spec.md` Section 9a (CI
bullets 1-5); Section 3.5 soft-spot 5 (PEP 440 rule); Section 15 (future
hard-error promotion).
