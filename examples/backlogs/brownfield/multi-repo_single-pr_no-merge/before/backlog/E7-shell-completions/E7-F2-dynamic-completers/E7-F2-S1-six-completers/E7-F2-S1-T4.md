## Description

Implement the `__complete_catalog_versions` dynamic completer
(Section 11.3 row 4). New hidden subcommand
`kanon __complete_catalog_versions <current-token>` that:

1. Resolves the manifest repo via the same global
   `--catalog-source` / `${KANON_CATALOG_SOURCE}` resolution as
   E7-F2-S1-T1.
2. Reads through the cache from E7-F3 (`catalogs/<sha>/tags.txt`).
   On cache hit, return immediately. On cache miss / stale, fetch
   via `git ls-remote --tags + --heads <manifest-repo-url>`,
   bounded by `KANON_COMPLETION_TIMEOUT`.
3. Applies the PEP 440 tag-name filter: tags whose LAST path
   component (after the final `/` in the ref name) is not parseable
   via `packaging.version.Version` are EXCLUDED. Branches are
   passed through unfiltered (only tags are PEP 440-filtered).
4. Deduplicates (a tag name and a branch name with the same string
   collapse to one entry), filters by prefix-match against
   `<current-token>`, emits one ref name per line, sorted
   deterministically (tags first by `packaging.version.Version`
   ordering, then branches alphabetically).

The PEP 440 filter function MUST be factored into a shared helper
(`src/kanon_cli/completions/pep440_filter.py`) so E7-F2-S1-T5
(`__complete_project_versions`) reuses it. The helper exposes:

```python
def filter_pep440_tags(refs: Iterable[str]) -> list[str]: ...
def is_pep440_tag(ref_last_component: str) -> bool: ...
```

Failure handling identical to T1/T2/T3.

Spec source: spec Section 11.3 row 4 (catalog-versions completer),
Section 0.4 (PEP 440 tag-name enforcement -- "tab-completion silently
drops non-PEP-440 tag names"), Section 11.2 row for
`--since-version <spec>`.
