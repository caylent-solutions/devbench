## Description

Add the `--fail-on-upgrade` flag to `kanon outdated` (implemented in `src/kanon_cli/commands/
outdated.py`). Per spec Section 0.2 and Section 4.4 "Exit code":

- Default exit code is 0 always (the behaviour T1 already lands), regardless of upgrade
  availability. This mirrors `pip list --outdated`, `npm outdated`, and `cargo outdated`.
- With `--fail-on-upgrade`, the command exits 1 when ANY source has an available upgrade. This is
  the CI-gate use case: a workflow runs `kanon outdated --fail-on-upgrade` and the build fails
  when any source is upgradable, prompting the operator to refresh the lockfile.

"Has an available upgrade" is defined as: the row's `upgrade-type` column reads any value OTHER
than `none`. Specifically, `patch`, `minor`, `major`, `prerelease`, and `drift` (the T2 value for
branch-pinned drift) all count as "available upgrade" for the purpose of the flag. `none` does not.

The flag is wired through the argparse subparser (a boolean store-true). Default value `False`.
Output stays unchanged in either mode (the row content does not depend on the flag); only the exit
code differs.

Spec source: `spec/kanon-list-add-lock-features-spec.md` Section 0.2 (`outdated` exit-code
policy) and Section 4.4 "Exit code" paragraph.
