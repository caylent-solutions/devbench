# E1-F1: Resolver semantics in `version.py`

## Status: in-queue

## Description

Two surgical changes to `src/kanon_cli/version.py`, the existing version
constraint resolver:

1. **Widen `_normalize_bare_semver_to_tag`** so bare PEP 440 specs that
   are not narrow `\d.\d.\d` (prereleases, local versions, calendar
   versions) ALSO get prepended with `refs/tags/`. Today the regex
   `_BARE_SEMVER_RE = ^\d+(?:\.\d+){1,2}$` only accepts `1`, `1.0`, `1.0.0`.
   After this feature, any input that parses cleanly via
   `packaging.version.Version(<spec>)` and contains no `/` is normalised
   to `refs/tags/<spec>`. PEP 440 prereleases (`1.0.0a1`), local versions
   (`1.0.0+local.build`), calendar versions (`2026.4.1`), and PEP 440
   post-/dev-releases all resolve to tags.

2. **Make `_resolve_constraint_from_tags` loud on zero-PEP-440-tags**.
   Today, when every candidate tag's last path component fails
   `Version()` parsing, the function raises a generic
   `"No parseable version tags found under '<prefix>'"`. After this
   feature, the error message ALSO lists the non-PEP-440 tag names that
   were skipped (capped at the first 10 to keep the message readable),
   plus a remediation pointer to `kanon catalog audit --check tag-format`.
   This implements spec Section 0.4.

Both changes preserve today's success paths byte-for-byte; only error
shape and the bare-spec acceptance widen. The function signature, return
type, and call sites are unchanged.

Spec source: spec Section 4.0 resolver rule 3 (widened bare PEP 440) and
spec Section 0.4 (PEP 440 tag-name enforcement loud-error).
