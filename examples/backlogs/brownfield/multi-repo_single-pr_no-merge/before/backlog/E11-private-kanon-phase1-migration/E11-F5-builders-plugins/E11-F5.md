# E11-F5: Audit the `builders-plugins` catalog entry (XML-only; no legacy catalog dir)

## Status: in-queue

## Description

Bring the `builders-plugins` catalog entry into Section 3.5 soft-spot
compliance. The entry's manifest XML lives at
`repo-specs/common/builders/builders-plugins/builders-plugins-marketplace.xml`.
There is NO matching `catalog/builders-plugins/` directory in the repo,
so there is no legacy README to migrate; this feature is therefore a
pure metadata audit + `<name>` addition rather than a README migration.

Today's `<catalog-metadata>` block carries `display-name="Builders
Plugins"`, `type`, `description`, `owner-name`, `owner-email`, `keywords`,
and `version="1.0.0"` as attributes but is MISSING the REQUIRED `<name>`
element. The single referenced `<project>` revision pins the branch
`main` (NOT a tag) against the inherited `caylent` remote (resolved via
`repo-specs/git-connection/remote.xml`); a branch-pin is NOT a PEP 440
tag, so the soft-spot 5 tag-format check is not applicable to this entry
(`kanon catalog audit --check tag-format` does not flag branch pins).
However: spec Section 9b Phase 1 says "if any [referenced revisions are
not PEP 440-compliant tags], file an upstream issue and document in the
entry's description." Since `main` is a branch (intentional, not a
mistake), the remediation is to document the branch-pin choice in
`<description>` (no upstream issue filing required for a deliberate
branch-pin).

Today's `<description>` attribute also contains a Unicode em-dash
character ("AI agent skills ... Builders team -- EVO platform ...");
this MUST be replaced with `--` (double hyphen) per the no-em-dashes
rule (`AC-FINAL-012` and CLAUDE.md). The task includes this cleanup.

This feature decomposes into a single story (`E11-F5-S1`) with a single
task (`E11-F5-S1-T1`).

Spec source: spec Section 9b Phase 1; Section 3.5 soft-spot rules 1-5.
