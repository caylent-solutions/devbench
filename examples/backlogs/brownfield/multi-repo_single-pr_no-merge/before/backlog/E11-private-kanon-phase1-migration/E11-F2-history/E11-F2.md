# E11-F2: Migrate the `history` catalog entry

## Status: in-queue

## Description

Bring the `history` catalog entry into Section 3.5 soft-spot compliance.
The entry's manifest XML lives at
`repo-specs/common/claude-tools/history/claude-history-marketplace.xml`
and the legacy author-facing README lives at `catalog/history/README.md`.

**Entry-name resolution.** The XML filename uses `claude-history-` as a
prefix but the legacy catalog directory is named `history/`. The two
plausible entry-names are `claude-history` (matches XML filename) and
`history` (matches the catalog directory). We choose `history` to keep
continuity with the existing author-facing surface area (the catalog
directory name is what authors and operators have been referring to up
to now). The rename rationale is documented in the entry's `<description>`
when migrated.

Today's `<catalog-metadata>` block carries `display-name="History Mining"`,
`type`, `description`, `owner-name`, `owner-email`, `keywords`, and
`version` as attributes but is MISSING the REQUIRED `<name>` element.
The single referenced `<project>` revision pins
`refs/tags/claude-tools/history/>=0.2.0,<1.0.0` against the inherited
`caylent` remote (resolved via `repo-specs/git-connection/remote.xml`);
the PEP 440 last-path-component of that constraint is `>=0.2.0,<1.0.0`,
which IS PEP 440 compliant.

This feature decomposes into a single story (`E11-F2-S1`) with a single
task (`E11-F2-S1-T1`).

Spec source: spec Section 9b Phase 1; Section 3.5 soft-spot rules 1-5.
