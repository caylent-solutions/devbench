# E7-F1: `kanon completion <shell>` subcommand and PREAMBLE

## Status: in-queue

## Description

Two artefacts that together produce the script the operator installs:

1. **`kanon completion bash | zsh` subcommand** (Section 11.1). New
   `src/kanon_cli/commands/completion.py` that registers a top-level
   `kanon completion <shell>` subcommand. The handler calls
   `shtab.complete(parser, shell, preamble=PREAMBLE)` and writes the
   resulting script to stdout. `<shell>` is a static enum with choices
   `bash` and `zsh`. The subcommand is registered in `src/kanon_cli/cli.py`
   next to the existing subcommands. `pyproject.toml` adds
   `shtab>=1.7.0` to runtime dependencies.

2. **PREAMBLE shell helpers** (Section 11.1 implementation paragraph
   plus Section 11.5 mid-token splitter helper). New
   `src/kanon_cli/completions/preamble.py` defining a `PREAMBLE` dict
   keyed by shell name (`{"bash": <bash-preamble>, "zsh": <zsh-preamble>}`).
   Each preamble defines the kanon-specific shell helper functions
   that the dynamic completers call out to (e.g., the bash helper
   `_kanon_complete_catalog_entries()` shells out to
   `kanon __complete_catalog_entries "$cur"`, captures stdout, hands
   it to `COMPREPLY`). The mid-token splitter helper (Section 11.5)
   lives in both the bash and zsh preambles.

Spec source: spec Section 11.1, 11.2 (the `kanon completion` row), and
11.5 (mid-token splitter helper).
