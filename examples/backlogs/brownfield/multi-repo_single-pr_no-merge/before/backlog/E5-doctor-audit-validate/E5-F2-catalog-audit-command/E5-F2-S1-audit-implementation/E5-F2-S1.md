# E5-F2-S1: `kanon catalog audit` implementation (framework + five checks + legacy-dir + strict)

## Status: in-queue

## Description

Implement `kanon catalog audit` in eight atomic tasks. Each task is one
source-file edit + one or more matching test files; tasks build coherent
slices onto the same `src/kanon_cli/commands/catalog.py` file:

- T1 -- Framework. `kanon catalog audit` subcommand registration in
  `cli.py`. `--check` argparser accepting comma-separated subset names OR
  `all` (default). Empty list, invalid name, or `all,<other>` mix triggers
  hard error. Default positional arg `.` (cwd as manifest-repo root); also
  accepts directory path OR `<url>@<ref>` (clones to cache, audits there).
- T2 -- `--check metadata` (soft-spot 1). REQUIRED fields: `name`,
  `display-name`, `description`, `version`. RECOMMENDED: `type`,
  `owner-name`, `owner-email`, `keywords`. Errors on missing REQUIRED;
  warns on missing RECOMMENDED. Duplicate child elements within a
  `<catalog-metadata>` block => error. Multiple `<catalog-metadata>`
  blocks per XML => error.
- T3 -- `--check source-name-derivation` (soft-spot 2). Warns when the
  normalised form differs from the entry name. Warns when the entry name
  contains characters outside `[a-zA-Z0-9_-]`.
- T4 -- `--check entry-name-uniqueness` (soft-spot 3). Errors on
  collisions across XML files, naming every offending XML path.
- T5 -- `--check remote-url` (soft-spot 4). Resolves every `<project
  remote="X">` to a concrete fetch URL by walking `<include>` chains.
  Errors if unresolvable. Also checks the HTTPS-by-default policy.
- T6 -- `--check tag-format` (soft-spot 5; PEP 440). Warns about tags
  whose last path component is not a valid PEP 440 version. Warning-only.
  Scans `git ls-remote --tags`.
- T7 -- Legacy `catalog/<name>/` directory detection. Warning (not error)
  during deprecation window. Message: "Legacy catalog/ directory detected;
  this directory is unused by kanon >= <this-version> and should be
  deleted; see docs/migration-bootstrap-to-add.md".
- T8 -- `--strict` flag. Promotes every warning to an error (exit
  non-zero on any warning).

Each task's tests cover the success path and every documented error path.
AC-CYCLE evidence is required for every task: each constructs a real
fixture manifest repo (with valid + broken `*-marketplace.xml` files) and
runs the full audit end-to-end.

Spec source: spec Section 3.5 (soft-spot rules) and Section 4.8 (`kanon
catalog audit`) and Section 3.6 (HTTPS-by-default).
