# E3-F3-S1-T2: `--refresh-lock` flag for `kanon install`

## Status: in-queue

## Description

Add the `--refresh-lock` boolean flag to `kanon install`. When present, the
flag overrides the state machine T1 introduced: kanon ignores the existing
lockfile entirely, re-resolves every transitive version from scratch, and
overwrites `.kanon.lock` with the new state. The flag's contract per spec
Section 4.7:

- `--refresh-lock` requires a CLI-supplied or environment-supplied catalog
  source. The lockfile-`[catalog].source` fallback path that T1 enables
  for the `lockfile-consistent` state is DISABLED on the refresh path,
  because the operator is explicitly rebuilding the lockfile and the
  refusal-to-fallback prevents silent reuse of a stale catalog source.
- `--refresh-lock` is mutually exclusive with `--refresh-lock-source`
  (T3). Both supplied at once is an argparse-level error.
- After a successful `--refresh-lock`, the info-line is `"lockfile
  rebuilt from .kanon (N sources, M projects)"` (the same info-line as
  the lockfile-absent state, since the operator's intent is equivalent).
- `--refresh-lock` does NOT touch the `.kanon` file; it rebuilds only the
  lockfile and the per-source workspaces under `.kanon-data/`.

Implementation surface:

- Add `--refresh-lock` to the argparse parser in
  `src/kanon_cli/commands/install.py`; default `False`. The flag is a
  pure-boolean store-true argparse action.
- Pass the resolved value through to
  `src/kanon_cli/core/install.py::install` as the new keyword argument
  `refresh_lock: bool = False`.
- Add the new branch to `_classify_install_state` (or, more cleanly, a
  separate `refresh_lock` short-circuit before classification): if
  `refresh_lock=True`, the function returns `InstallState.REFRESH_LOCK`
  regardless of lockfile presence or hash state.
- Add the refresh-lock catalog-source rule to `_resolve_catalog_source`:
  when `install_state == InstallState.REFRESH_LOCK`, the lockfile
  fallback is disabled; CLI/env must be set or raise
  `MissingCatalogSourceError` with a refresh-specific remediation line
  (`"--refresh-lock requires a CLI or env-var catalog source; the
  lockfile fallback is disabled on this path."`).
- Argparse mutual-exclusion: register `--refresh-lock` and
  `--refresh-lock-source` (T3 adds the latter) into the same
  `mutually_exclusive_group`. T2 only adds `--refresh-lock` to that
  group; T3 adds `--refresh-lock-source`. The group's parser-error text
  is the spec-standard form.

Spec source: `spec/kanon-list-add-lock-features-spec.md` Section 4.7 flags
table, `--refresh-lock` row.
