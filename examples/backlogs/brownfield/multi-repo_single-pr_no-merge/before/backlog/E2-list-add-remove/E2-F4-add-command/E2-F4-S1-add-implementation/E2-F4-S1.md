# E2-F4-S1: `kanon add` implementation across core, pre-flight, and zero-tags

## Status: in-queue

## Description

Single-story decomposition of the `kanon add` implementation. Three tasks
in strict sequence (T1 -> T2 -> T3) so the command file grows
incrementally and each pre-flight check lands with its own integration
coverage:

- **T1** Core add path: argparse subparser, entry lookup via
  `_parse_catalog_metadata`, source-name normalisation via
  `derive_source_name`, triple writing, standard-header creation.
- **T2** `--dry-run`, `--force`, and collision detection (within the
  requested set + against existing blocks in `.kanon`).
- **T3** Zero-PEP-440-tags loud error for the default-spec path plus a
  new git fixture under `tests/fixtures/catalogs/zero-pep440-tags/`.

Spec source: spec Section 4.2.
