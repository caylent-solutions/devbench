# E1-F1-S1-T1: Widen `_normalize_bare_semver_to_tag` to accept any PEP 440 Version

## Status: in-queue

## Target Repository

- **Repo:** `caylent-solutions/kanon`
- **Branch:** `backlog/e1-f1-s1-t1`

## Description

Replace the narrow `_BARE_SEMVER_RE = ^\d+(?:\.\d+){1,2}$` regex check in
`src/kanon_cli/version.py` (currently lines 124-153, function
`_normalize_bare_semver_to_tag`) with a `packaging.version.Version`-based
parse-attempt. After this change, any input string that (a) contains no `/`
and (b) parses cleanly via `packaging.version.Version(<spec>)` is normalised
to `refs/tags/<spec>`. Inputs already starting with `refs/`, hex SHAs
(40 or 64 hex chars), branch-name-shaped strings that fail PEP 440 parsing,
and anything with `/` continue to pass through unchanged.

The widened accept set MUST include all six PEP 440 shapes the spec
explicitly calls out:

1. PEP 440 prereleases (e.g., `1.0.0a1`, `1.0.0rc2`, `1.0.0b3`).
2. PEP 440 local versions (e.g., `1.0.0+local`, `1.0.0+local.build`).
3. Calendar versions (e.g., `2026.4.1`).
4. PEP 440 epochs (e.g., `1!2.0.0`).
5. PEP 440 post-releases (e.g., `1.0.0.post1`).
6. PEP 440 dev-releases (e.g., `1.0.0.dev0`).

The existing narrow shapes (`1`, `1.0`, `1.0.0`) continue to resolve to
`refs/tags/<spec>`. No behaviour changes for non-PEP-440 inputs.

Spec source: `spec/kanon-list-add-lock-features-spec.md` Section 4.0
resolver rule 3 (widened bare PEP 440) and Section 13 decision 14.

   parsing succeeds AND the spec contains no `/`, return
   `f"refs/tags/{spec}"`; otherwise return the input unchanged. The
