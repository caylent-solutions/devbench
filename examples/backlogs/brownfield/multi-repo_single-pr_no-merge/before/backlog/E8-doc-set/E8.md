# E8: Open-source doc set, `creating-manifest-repos.md` rewrite, and terminology cleanup

## Status: in-queue

## Description

Documentation epic for the `caylent-solutions/kanon` open-source repository. Ships the
entire operator- and author-facing doc surface for the `kanon list` / `kanon add` /
`.kanon.lock` feature set: 16 NEW docs under `docs/`, 4 substantive updates to
existing docs (including a full REWRITE of `docs/creating-manifest-repos.md`), a
top-level `README.md` overhaul, and a Keep-a-Changelog `CHANGELOG.md` entry set.

The epic also enforces the canonical terminology table from spec Section 1.1 across
every doc touched in this backlog: "manifest repo" is the catalog, `<catalog-metadata>`
is the single source of truth for entry identity, source-name derivation is one-way
and lossy, and the legacy `catalog/<name>/` directory is removed from both manifest
repos and the bundled kanon wheel.

Doc-only epic. No Python source, no test code. All task files have language tier
`Markdown` and use the canonical `ac-final-markdown.md` AC-FINAL block (with the
`-- N/A for Markdown Tasks (no Python source authored)` suffix on every
Python-tooling AC per `devbench/docs/acceptance-criteria-canonical.md`).

Decomposed into three features:

- **E8-F1 -- New docs (16 tasks):** one task per new file in `docs/`. Each task
  reads its corresponding bullet from spec Section 8 verbatim, plus the spec
  sections referenced from that bullet, and authors a complete operator-facing
  document.
- **E8-F2 -- Existing doc updates (4 tasks):** targeted updates to
  `docs/version-resolution.md`, `docs/configuration.md`, `docs/multi-source-guide.md`,
  and a full REWRITE of `docs/creating-manifest-repos.md` to remove all references
  to the legacy `catalog/<name>/` directory tree.
- **E8-F3 -- README + CHANGELOG (2 tasks):** top-level `README.md` overhaul (new
  Quick start, Subcommands table, cross-links to feature docs) and the
  Keep-a-Changelog `CHANGELOG.md` entry set.

Spec source: `spec/kanon-list-add-lock-features-spec.md` Section 8 (Documentation
updates), Section 1.1 (Terminology), Section 3.5 (Standards audit / soft-spot
rules), Section 3.6 (Trust model), Section 11.7 (Shell-completion docs
requirement), and references throughout.
