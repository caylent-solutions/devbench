# E2-F3: `derive_source_name()` helper

## Status: in-queue

## Description

Introduce the canonical entry-name to source-name normalisation helper.
Every command in this release that touches a `.kanon` triple
(`kanon add`, `kanon remove`, `kanon why`, `kanon install
--refresh-lock-source`) calls this helper to translate the operator's
input (which may be either the original entry name or the already-normalised
source name) into the canonical `<source-name>` token used inside
`KANON_SOURCE_<source-name>_{URL,REVISION,PATH}` triples.

Soft-spot rule 2 (spec Section 3.5) makes the rule unconditional:

> The source name used in `KANON_SOURCE_<source-name>_*` triples is derived
> from `<catalog-metadata><name>` by deterministic normalization: **always
> lowercase the input AND always replace `-` with `_`.** No conditional
> logic; same input always yields same output.

The helper lives in the new module `src/kanon_cli/core/metadata.py`
(extending the file introduced by E2-F1-S1-T1) so the two shared helpers
ride together. It emits a single-line warning to stderr when the input
contains any character outside `[a-zA-Z0-9_-]` (still legal; flagged for
author awareness, per soft-spot rule 2).

Idempotence is guaranteed by construction: `derive_source_name(x) ==
derive_source_name(derive_source_name(x))` for every legal input.

Spec source: spec Section 3.5 soft-spot rule 2 and spec Section 1.1
terminology row "source name".
