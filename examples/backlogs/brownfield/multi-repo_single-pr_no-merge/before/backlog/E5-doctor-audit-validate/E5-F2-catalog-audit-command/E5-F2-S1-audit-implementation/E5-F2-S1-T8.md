## Description

Implement the `--strict` flag inside
`src/kanon_cli/commands/catalog.py` per spec Section 4.8 last paragraph
and the flag row in the audit table.

Behaviour:

- The `--strict` flag was declared at argparse time by T1 (parsed and
  stored on `args`); T1 did NOT change exit-code behaviour. This task
  consumes the parsed value in `audit_command`.
- After every registered check + the unconditional legacy-directory
  check have run and collected findings, if `args.strict` is true, every
  finding with `kind == "warn"` is treated as an error for the purposes
  of the final exit code: any warning => non-zero exit code (1).
- The findings themselves are NOT mutated. The display still prints
  `WARN:` for warnings (so an operator running with and without
  `--strict` sees consistent output and can tell which findings were
  warnings vs errors), but the exit code computation considers warnings
  as failing under `--strict`.
- An additional one-line summary printed to stderr at end of run when
  `--strict` is active AND warnings exist:
  "strict mode: <count> warning(s) treated as errors". This makes the
  reason for the non-zero exit clear.

The exit-code rule:

- Default mode: exit 1 if any ERROR finding, else exit 0.
- `--strict` mode: exit 1 if any ERROR or WARN finding, else exit 0.

Source-test atomicity: this task modifies `catalog.py` (existing after
T1-T7) and adds new tests. No new fixtures are needed -- the test
reuses fixtures from T2-T7 by invoking `--check` on subsets known to
produce warnings without errors (e.g., `source-name-derivation`
against `broken-soft-spot-2/`, or `tag-format` against a mixed-tags
fixture repo).

Spec source: spec Section 4.8 (`--strict` flag).
