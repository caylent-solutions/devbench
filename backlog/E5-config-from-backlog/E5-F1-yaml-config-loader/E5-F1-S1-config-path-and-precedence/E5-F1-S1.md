## Description

This story implements the configuration loading contract for DevBench. It defines where config is loaded from, how values are merged with environment variables, and how repository-level settings (including optional default branch) are consumed by existing runtime behavior. It explicitly avoids broad CLI changes and relies only on the existing top-level `--config` path input.

## Acceptance Criteria

- [ ] AC-1: Default config path is `backlog/config/devbench.yaml`
- [ ] AC-2: Config path precedence is `--config` (top-level runner) > `CONFIG_PATH` env > default path
- [ ] AC-3: Value precedence is `env > yaml > code default`
- [ ] AC-4: YAML includes `repos` map keyed by full `org/repo`; each entry allows optional `default_branch`
- [ ] AC-5: Missing `default_branch` uses `origin/HEAD` fallback
- [ ] AC-6: Runtime branch consumers use shared branch resolution logic
- [ ] AC-7: `src/devbench/cli.py` gains no new arguments/options for this change
- [ ] AC-8: YAML supports optional `repos.<org/repo>.checkout_directory`, resolved relative to `JUDGE_WORKSPACE_ROOT`
- [ ] AC-9: `checkout_directory` rejects absolute paths and `..` traversal; omitted value defaults to repo short-name directory
- [ ] AC-10: Orchestrator canonicalizes `work_unit.repo` once and uses canonical repo for repo validation, local path lookup, and downstream repo calls
- [ ] AC-11: `JUDGE_BACKLOG_ROOT` and `JUDGE_BACKLOG_INDEX` are deprecated with warning-only behavior; runtime backlog paths derive from `JUDGE_WORKSPACE_ROOT`

### Contract Definition

Configuration path selection and merged runtime config are deterministic:

1. path: `--config` > `CONFIG_PATH` > `backlog/config/devbench.yaml`
2. values: `env` overrides `yaml`
3. branch: `repo.default_branch` or `origin/HEAD`
