## Description

Add JSON output to `kanon outdated`. Per spec Section 4.4 + Section 7 flag table, the `--format`
flag supports both `table` (default, from T1) and `json`. T4 extends the choices set from
`("table",)` to `("table", "json")` and adds the JSON formatter.

The JSON shape mirrors the table row-for-row: a top-level array; one object per source; each
object has exactly the same five fields as the table columns:

```json
[
  {
    "name": "<source-name>",
    "current": "<sha-or-tag-or-ref>",
    "latest-matching-spec": "<sha-or-tag-or-ref>",
    "latest-available": "<sha-or-tag-or-ref>",
    "upgrade-type": "none|patch|minor|major|prerelease|drift"
  }
]
```

Notes:

- Field names use hyphens (matching the table column headers) for parity with the human-readable
  output. This is the spec's documented shape.
- Output is emitted via `json.dump(...)` with `sort_keys=False, indent=2` (a constant in
  `constants.py` controls the indent so it can be tuned without source edits). A trailing newline
  is appended for POSIX-tool friendliness.
- For branch-pinned and SHA-pinned sources, the `current` / `latest-matching-spec` / `latest-
  available` fields contain the 12-char truncated SHA (consistent with T2's table output).
- `--fail-on-upgrade` (T3) interacts unchanged with JSON output: exit code logic is independent of
  format.
- The default format remains `table` via `KANON_OUTDATED_FORMAT`. Operators select JSON by passing
  `--format json` or by setting `KANON_OUTDATED_FORMAT=json` in the environment.

Spec source: `spec/kanon-list-add-lock-features-spec.md` Section 4.4 (`--format {table,json}`) and
Section 7 flag table.
