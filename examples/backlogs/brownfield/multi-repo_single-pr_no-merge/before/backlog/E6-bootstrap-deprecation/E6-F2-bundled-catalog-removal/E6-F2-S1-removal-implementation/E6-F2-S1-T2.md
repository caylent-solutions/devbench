# E6-F2-S1-T2: Remove third-tier "bundled fallback" from `resolve_catalog_dir`

## Status: in-queue

## Target Repository

- **Repo:** `caylent-solutions/kanon`
- **Branch:** `backlog/e6-f2-s1-t2`

## Description

Modify `src/kanon_cli/core/catalog.py::resolve_catalog_dir` so when
neither `--catalog-source` nor `KANON_CATALOG_SOURCE` is set, the
function raises the canonical missing-catalog error from spec
Section 4 (verbatim text) instead of returning the bundled directory.
Today's lines 40-49 implement the fallback as
`return _get_bundled_catalog_dir()`; after this task, the function
hard-fails fast.

The canonical missing-catalog error message (verbatim, including
newlines and exact wording per spec Section 4) -- the calling
command interpolates its own command name in place of `<command>`:

```
ERROR: <command> requires a catalog source.
Provide one of:
  --catalog-source <git-url>@<ref>      # e.g. --catalog-source https://example.com/org/manifest-repo.git@main
  KANON_CATALOG_SOURCE=<git-url>@<ref>  # set as env var, then re-run
The CLI flag takes precedence when both are set.
A catalog source identifies a manifest repo (a git repository whose
repo-specs/ directory exposes installable kanon dependencies).
See docs/catalogs-explained.md for what a manifest repo is and how to find one.
See docs/configuration.md for the full configuration reference.
```

The error is implemented as a new exception class
`MissingCatalogSourceError(ValueError)` inside `core/catalog.py`. The
calling command (today only `kanon bootstrap`, which is now an
exit-3 shim and never reaches the resolver; tomorrow `kanon list`,
`kanon add`, `kanon outdated`, etc. landing in later epics) catches
the exception, formats the canonical text with its own command name,
and writes to stderr / exits 1. Per the spec Section 4 header, the
following commands hard-error on missing source: `list`, `add`,
`outdated`, `why`, `catalog audit`. `install` and `doctor` retain a
lockfile fallback (separate code path, not affected by this task).

Concretely:

- Add `MissingCatalogSourceError(ValueError)` class to
  `core/catalog.py` carrying no fields beyond the exception message
  (the calling command does the message formatting; the exception
  itself is a marker indicating the resolver could not produce a
  source).
- Rewrite `resolve_catalog_dir`: drop the
  `return _get_bundled_catalog_dir()` line; when `source` is
  falsy after the CLI / env merge, raise `MissingCatalogSourceError()`
  with no args (the caller supplies the formatted message).
- Delete the `_get_bundled_catalog_dir()` helper entirely. Verify
  zero remaining consumers via `grep -rn "_get_bundled_catalog_dir"
  src tests` -- only the pre-task definition + the imports it
  triggers should match before deletion; after deletion, zero
  matches.
- Update / replace every existing test that exercised the bundled-
  fallback success path. Today's `tests/unit/test_catalog.py` (if
  present) likely has a parametrised case asserting
  `resolve_catalog_dir(None)` returns a path under
  `kanon_cli/catalog`; that case becomes `resolve_catalog_dir(None)
  raises MissingCatalogSourceError`.
- Add new integration test
  `tests/integration/test_no_default_catalog.py` that confirms the
  end-to-end behaviour: with `KANON_CATALOG_SOURCE` unset and no
  `--catalog-source` flag, the resolver raises and the CLI command
  surfaces the canonical missing-catalog error to stderr.

After this task lands, the only ways to invoke a command needing a
catalog source are (a) the `--catalog-source` flag, (b) the
`KANON_CATALOG_SOURCE` env var, or (for `install` / `doctor`) (c)
the lockfile's `[catalog].source` field. There is no implicit
default. This matches spec Section 13 decision 19 ("no default
manifest repo").

Spec source: `spec/kanon-list-add-lock-features-spec.md` Section 4
header (verbatim missing-catalog error message + "The bundled
`src/kanon_cli/catalog/` directory is deleted by this spec's
bootstrap-deprecation epic; the existing third-tier 'bundled
fallback' in `resolve_catalog_dir()` is removed at the same time.")
plus Section 13 decision 19 (no default manifest repo).

#### Critical Rules (Violation = Automatic Rejection)

1. **NO FALLBACK LOGIC** -- If an operation can fail, it MUST fail loudly. Never catch an exception and silently continue. Never provide a default value when the real value is missing. Exceptions: the resolver's documented lockfile-catalog-source fallback for `kanon install` / `kanon doctor`, and the existing `git ls-remote` retry policy (`KANON_GIT_RETRY_COUNT` / `KANON_GIT_RETRY_DELAY`) -- both in `spec/kanon-list-add-lock-features-spec.md` Section 4 header and Section 7.
2. **NO SILENT FAILURES** -- Every error must produce a clear, actionable error message sent to stderr. Every error must result in a non-zero exit code. Never swallow exceptions. Never log-and-continue when the operation was required to succeed.
3. **FAIL FAST** -- Detect errors at the earliest possible point. Validate inputs before processing. Check prerequisites before starting work. Exit immediately on the first error with a message that tells the user exactly what went wrong and what to do about it.
4. **NO HARD-CODED VALUES** -- No URLs, paths, timeouts, retry counts, port numbers, hostnames, credentials, feature flags, or environment-specific values in source code. All constants live in `src/kanon_cli/constants.py`, never inline in source files. All configuration comes from environment variables, configuration files, or function parameters.
5. **NO TEMPORAL LOGIC** -- Never use `time.sleep()`, `asyncio.sleep()`, or any time-based delay as a synchronization mechanism. The existing `KANON_GIT_RETRY_DELAY` (wait between known-failed `git ls-remote` retries) is the ONLY allowed sleep-based wait in this codebase. Use readiness detection, event-driven callbacks, or polling with configurable timeouts everywhere else.
6. **ALL CODE MUST BE DYNAMIC AND INPUT-DRIVEN** -- No static data, no hard-coded test fixtures embedded in source, no magic numbers. All thresholds, limits, paths, and identifiers must be parameterized.
7. **NO BYPASS ANNOTATIONS** -- Never add `# noqa`, `# nosec`, `# type: ignore`, `# pragma: no cover`, or any annotation that suppresses a linter, type checker, or security scanner finding. Fix the finding instead. The kanon repo has a documented vendored carve-out for `src/kanon_cli/repo/` (the embedded repo-tool fork): mypy and bandit scope to non-vendored code only. This carve-out is a scope demarcation, NOT a bypass annotation; do not extend it to new paths.
8. **NO DASH-EMS IN CODE OR TESTS** -- Do not use the em-dash character (Unicode U+2014) in any source file, test file, or work-unit `.md` file. Use `--` (double hyphen) in comments and docstrings if a dash is needed. `devbench validate-backlog` rule 10 enforces this on work-unit files.
