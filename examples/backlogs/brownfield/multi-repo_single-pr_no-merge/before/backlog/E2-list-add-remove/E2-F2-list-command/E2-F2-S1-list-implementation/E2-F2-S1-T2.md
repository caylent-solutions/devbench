## Description

Extend the `kanon list` command (introduced by E2-F2-S1-T1) with the
`--detail` flag per spec Section 4.1 flag-table row `--detail`.

Behaviour:

- When `--detail` is set, the command still walks
  `repo-specs/**/*-marketplace.xml` and parses each entry's
  `<catalog-metadata>` via `_parse_catalog_metadata()`. Instead of emitting
  one entry name per line, it emits a multi-line human-readable record per
  entry with the fields: `name`, `display-name`, `type`, `description`,
  `version`. Matches the worked-example shape in spec Section 2.1 (step 2).
- Output is human-readable and NOT pipeable into `kanon add`. The flag is
  marked accordingly in the help text.
- For machine consumers, `--detail` combines with `--format json`
  (introduced by E2-F2-S1-T5); the JSON output is the structured form of the
  same field set.
- The `--detail` flag is compatible with the filter framework (positional
  substring, `--regex`, `--match-fields`) introduced by E2-F2-S1-T6, but
  not with `--tree` (which is its own per-entry mode introduced by
  E2-F2-S1-T3) and not with `--all-versions` (introduced by E2-F2-S1-T4).
  The cross-flag mutual-exclusion checks are added by their respective tasks;
  this task only adds `--detail` itself.
- Recommended-field warnings emitted by `_parse_catalog_metadata()` still
  surface to stderr; `--detail` simply changes the stdout format.
