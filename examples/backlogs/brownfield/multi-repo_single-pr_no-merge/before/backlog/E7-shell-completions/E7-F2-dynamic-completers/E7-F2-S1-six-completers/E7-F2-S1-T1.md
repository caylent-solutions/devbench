## Description

Implement the `__complete_catalog_entries` dynamic completer (Section
11.3 row 1). New hidden subcommand `kanon __complete_catalog_entries <current-token>`
that:

1. Resolves the manifest repo via the global `--catalog-source` /
   `${KANON_CATALOG_SOURCE}` resolution chain (shared with the rest
   of the CLI; do NOT reimplement -- import from
   `src/kanon_cli/core/catalog_source.py`).
2. Uses the cache layer from E7-F3 (`catalogs/<sha>/index.txt`) to
   serve the candidate list. On cache hit within
   `KANON_COMPLETION_CACHE_TTL`, returns immediately. On cache miss
   or stale, performs the network-bounded fetch (clone + cache)
   inside `KANON_COMPLETION_TIMEOUT`, enumerates
   `repo-specs/**/*-marketplace.xml`, parses each via the existing
   `parse_catalog_metadata` helper (E2-F1-S1-T1), writes the
   `<catalog-metadata><name>` values to `index.txt`, and returns
   them.
3. Filters the candidate list by prefix-match against the
   `<current-token>` argument (case-sensitive, mirroring shell
   completion conventions). The shell helper then narrows further
   via `compgen`.
4. Emits one entry name per line to stdout. Trailing newline on
   the last line.

Failure handling:

- **Failure-quiet on stdout**: on any error (network failure, parse
  error, missing manifest, cache write failure), stdout is empty.
- **Failure-loud on stderr**: every error path writes a structured
  one-line entry to `${KANON_CACHE_DIR}/completion-errors.log` (the
  path resolved via the constant `KANON_COMPLETION_LOG` from
  `constants.py`). Format: `<ISO-8601> __complete_catalog_entries <error-class>: <message>`.
- `KANON_COMPLETION_ENABLED=0` -> emit nothing, return exit 0, do
  not touch cache, do not log.

Registration: `src/kanon_cli/cli.py` UPDATE -- register the hidden
subcommand alongside the existing visible subcommands. Hidden in the
sense that `argparse` flags it with `help=argparse.SUPPRESS` so it
does not appear in `kanon --help` (operators do not invoke it
directly; the shell preamble does).

Spec source: spec Section 11.3 row 1 (catalog-entries completer),
Section 11.4 (cache lifecycle), Section 11.3 "Output sanitization"
paragraph, Section 3.6 trust model.
