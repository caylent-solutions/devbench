## Description

Create a new module `src/kanon_cli/core/url.py` exposing a single
public function:

```python
def canonicalize_repo_url(url: str) -> str:
    """Return the canonical form of a git repository URL.

    Two URLs identify the same repository iff
    canonicalize_repo_url(a) == canonicalize_repo_url(b).
    """
```

Canonicalisation rules (spec Section 4.0 "Repo URL canonicalization"):

1. Detect the input scheme. Accept three equivalent shapes:
   - `https://host[:port]/path` -- standard HTTPS.
   - `ssh://[user@]host[:port]/path` -- explicit SSH.
   - `git@host:path` -- SCP-like SSH shorthand (no scheme prefix; the
     `:` after the host is the path separator).
2. Lowercase the host. Path case is preserved verbatim (some hosts are
   case-sensitive on path).
3. Strip embedded user-info (everything between the scheme and `@host`,
   if an `@` precedes the host). For the SCP shorthand `user@host:path`,
   strip `user@` as well.
4. Strip exactly one trailing `/` from the path (if present).
5. Strip exactly one trailing `.git` suffix from the path (if present).
   The strip is applied after the trailing-slash strip so
   `https://h/r.git/` and `https://h/r.git` produce the same output.
6. Normalise the scheme: always emit `https://<host>/<path>` regardless
   of the input scheme. The three equivalent inputs `https://h/r`,
   `ssh://git@h/r`, and `git@h:r` all canonicalise to `https://h/r`.
7. If the input contains a query string (`?...`) or fragment (`#...`),
   raise `ValueError` with a message naming the offending input and
   explaining that canonicalisation output is undefined for those
   shapes. The error message follows the spec Section 4 error shape
   (`ERROR: <summary>` then context then remediation).
8. Empty input or whitespace-only input raises `ValueError` immediately.

The function MUST be a pure function (no I/O, no globals, no logging).
All input-shape detection is via the standard library (`urllib.parse`)
plus regex; no third-party dependencies are added.

Spec source: `spec/kanon-list-add-lock-features-spec.md` Section 4.0
"Repo URL canonicalization" subsection.
