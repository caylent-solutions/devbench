## Description

Implement the cache TTL math from Section 11.4 cache lifecycle.

API added to `src/kanon_cli/completions/cache.py`:

```python
class Freshness(enum.Enum):
    FRESH = "fresh"          # fetched_at within TTL
    STALE = "stale"          # fetched_at outside TTL but file exists
    MISSING = "missing"      # no fetched_at file, or unreadable, or negative
                             # (clock-skew lower bound) or non-numeric

def classify(fetched_at_path: Path, ttl_seconds: int, now: int) -> Freshness: ...
```

Rules (verbatim from Section 11.4 cache lifecycle and the
clock-skew bullet):

- `fetched_at` absent on disk -> `MISSING`.
- `fetched_at` content not parseable as an integer -> `MISSING`.
- `fetched_at` < 0 -> `MISSING`.
- `fetched_at` > now (clock skew, future timestamp) -> `FRESH`
  (the spec is explicit: "`fetched_at` in the future -> treat as
  fresh").
- `now - fetched_at <= ttl_seconds` -> `FRESH`.
- `now - fetched_at > ttl_seconds` -> `STALE`.

The TTL value is sourced from `${KANON_COMPLETION_CACHE_TTL}` via
the constant; `now` is injected as a parameter for testability (in
production, callers pass `int(time.time())`; tests pass fixed
values).

The `classify` function is pure; no side effects. The caller
(`read_entries_with_freshness` -- a thin wrapper added in this task)
uses `classify` to decide whether to return `(entries, FRESH)` immediately,
return `(entries, STALE)` and let E7-F3-S1-T5 fork the background
refresh, or return `([], MISSING)` and let the caller refetch
inline.

Spec source: spec Section 11.4 (cache lifecycle + clock-skew
bullet), Section 11.6 (`KANON_COMPLETION_CACHE_TTL` constant).

   parametrized cases for every Freshness rule: missing file ->
   MISSING; empty file -> MISSING; non-numeric content -> MISSING;
   negative content -> MISSING; future timestamp (`fetched_at > now`)
