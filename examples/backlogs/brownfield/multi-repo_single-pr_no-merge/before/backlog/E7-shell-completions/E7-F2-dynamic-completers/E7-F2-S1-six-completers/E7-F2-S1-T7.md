## Description

Implement the mid-token splitter (Section 11.5). The splitter is
the shell function that the bash + zsh PREAMBLE installs as the
completer for the `<name>[@<spec>]` positional of `kanon add`. It
detects the `@` separator and routes to the appropriate dynamic
completer.

Logic (in both bash and zsh PREAMBLE; the Python helper described
below provides the entry-name -> repo-url lookup):

```
function _kanon_complete_add_arg() {
    local cur="$1"
    if [[ "$cur" == *@* ]]; then
        # split on the LAST @ per spec Section 4.0
        local name="${cur%@*}"
        local spec="${cur##*@}"
        local repo_url
        repo_url="$(kanon __resolve_entry_to_repo_url "$name")" || return
        _kanon_complete_project_versions "$repo_url" "$spec"
    else
        _kanon_complete_catalog_entries "$cur"
    fi
}
```

Two artefacts:

1. **Update PREAMBLE** (`src/kanon_cli/completions/preamble.py`):
   replace the placeholder body from E7-F1-S1-T2 with the real
   splitter logic in both bash and zsh dialects.
2. **New Python helper** (`src/kanon_cli/completions/midtoken.py`):
   exposes `resolve_entry_to_repo_url(entry_name: str) -> str` that
   reads the resolved manifest repo (via the cache from E7-F3),
   finds the `<catalog-metadata>` element whose `<name>` equals
   `entry_name`, and returns the `<source>`'s `<repo-url>` value.
   Registered as the hidden `kanon __resolve_entry_to_repo_url`
   subcommand the shell helper shells out to.

Edge cases handled by the splitter:

- `kanon add foo` (no `@`): routes to `__complete_catalog_entries "foo"`.
- `kanon add foo@` (empty spec): routes to `__complete_project_versions <repo-url-of-foo> ""`.
- `kanon add foo@1`: routes to `__complete_project_versions <repo-url-of-foo> "1"`.
- `kanon add foo@bar@baz` (multiple `@`): split on the LAST `@`
  per Section 4.0; name = `foo@bar`, spec = `baz`. Lookup is
  against entry name `foo@bar` (which most likely does not exist;
  the resolver returns empty and the completer emits empty).
- `kanon add @1.0.0` (leading `@`, empty name): name is empty;
  the entry-to-repo-url resolver returns empty; the splitter emits
  no candidates.

Failure handling: the Python helper follows the same
failure-quiet-on-stdout / failure-loud-on-stderr contract as the
six dynamic completers. `KANON_COMPLETION_ENABLED=0` causes the
shell-side splitter to return empty without invoking the Python
resolver.

Spec source: spec Section 11.5 (mid-token splitting), Section 4.0
(LAST-`@` split rule), Section 11.2 (`kanon add <name>[@<spec>]`
row).
