# E2-F5: `kanon remove` command

## Status: in-queue

## Description

Implement the new top-level `kanon remove` subcommand per spec
Section 4.3. The command is the inverse of `kanon add`: it strips named
source blocks from a `.kanon` file.

The feature ships as two sequential tasks in a single story:

- **T1** introduces the command shell, the core lookup-and-strip path
  (accepts either the source name like `foo_bar` OR the original entry
  name like `Foo-Bar`; both normalise via `derive_source_name()` before
  lookup), the fewer-than-three-keys hard error, and the registration on
  the top-level argparse parser.
- **T2** adds `--dry-run` plus the file-writing rules: per-file
  dominant-line-ending sniff (mixed normalises to `\n` with stderr
  warning), runs of three or more blank lines collapse to two, and file
  ends with exactly one trailing newline.

Spec source: spec Section 4.3.
