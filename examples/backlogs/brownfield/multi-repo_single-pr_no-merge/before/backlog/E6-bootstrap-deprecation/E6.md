# E6: `kanon bootstrap` deprecation shim and bundled `src/kanon_cli/catalog/` removal

## Status: in-queue

## Description

Convert `kanon bootstrap` and `kanon bootstrap list` into hard-stop
deprecation shims that print a WARN to stderr (with the verbatim
replacement command) and exit with status 3 without performing any
work, AND delete the bundled `src/kanon_cli/catalog/` directory from
the kanon wheel.

The shim does NOT delegate to `kanon add` / `kanon list`; the operator
runs the suggested replacement command explicitly. The shim does NOT
read from `<catalog-metadata>`, does NOT touch the filesystem, and
does NOT import `core/catalog.py` or `core/bootstrap.py`. The legacy
business module `src/kanon_cli/core/bootstrap.py` is deleted entirely.

The bundled catalog removal pairs with the shim: the third-tier
"bundled fallback" path inside `core/catalog.py::resolve_catalog_dir`
(today's lines 40-49, returning `_get_bundled_catalog_dir()`) is
deleted in the same epic so that no command silently picks up the
bundled tree after deletion. Once both land, the only valid catalog
sources are the `--catalog-source` CLI flag and the
`KANON_CATALOG_SOURCE` env var; missing-source invocations hard-fail
with the canonical error from spec Section 4.

E6 has NO upstream dep on E2/E3/E4/E5; it stands alone after E1-F4
(shared `core/cli_args.py`) lands. Splitting the two halves into F1
(shim) and F2 (bundled removal) keeps each PR reviewable in
isolation, and F2 depends on F1 because the self-bootstrap path
(`kanon bootstrap kanon` reading the bundled `catalog/kanon/.kanon`
template) must be neutralised before the bundled tree can go.
