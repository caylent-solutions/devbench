## Description

Implement the legacy-directory detection inside
`src/kanon_cli/commands/catalog.py` per spec Section 4.8.

The audit MUST detect the presence of a legacy `catalog/<name>/`
directory tree in the manifest repo and emit a warning. This is a single
top-level check that runs ALONGSIDE the five soft-spot checks (T2-T6);
it is NOT one of the five `--check` subset names. It runs whenever
`kanon catalog audit` runs, regardless of `--check` value.

Detection rule:

- Inside the audit target directory, look for a subdirectory named
  `catalog/`.
- If `catalog/` exists AND contains at least one immediate
  subdirectory => emit one WARN finding with the message from spec
  Section 4.8: "Legacy catalog/ directory detected; this directory is
  unused by kanon >= <this-version> and should be deleted; see
  docs/migration-bootstrap-to-add.md". `<this-version>` is the running
  kanon CLI version (from `__version__`).
- If `catalog/` exists but is empty (no subdirectories) => no finding
  (empty residual directory is harmless and may be a not-yet-cleaned
  git artifact).
- If `catalog/` does not exist => no finding.

The warning is NOT a hard error during the deprecation window; the
spec marks the warning-to-error promotion as future work (Section 15).
`--strict` (T8) WILL promote this warning to an error consistent with
the rest of the audit.

The detection helper (`_check_legacy_catalog_dir(target_path, version)`)
is NOT registered in the check-name registry T1 created (because it is
not selectable via `--check`); instead it is invoked unconditionally
by `audit_command` after the registered checks run.

Source-test atomicity: this task modifies `catalog.py` and adds tests.
Fixture: `tests/fixtures/catalog/legacy-catalog-dir/` with a sample
legacy tree.

Spec source: spec Section 4.8 paragraph beginning "The audit MUST detect
the presence of a legacy `catalog/<name>/` directory tree".
