# E12-F1-S1: `git rm -r catalog/` + reference scrub

## Status: in-queue

## Target Repository

- **Repo:** `caylent/caylent-private-kanon`

## Description

Single story: execute the `catalog/` deletion plus internal-tooling
reference scrub in one task on one branch.

Story scope:

1. Audit pass: run `git ls-files catalog/` to enumerate every tracked
   file under the legacy tree. Today's enumeration (as of the spec's
   authoring) yields 10 files across 5 subdirectories; the executor
   re-runs the enumeration at task time to capture the exact set.
2. Audit pass: run `git grep -F 'catalog/' caylent-private-kanon/`
   (from workspace root; `git grep -F 'catalog/'` from inside the
   repo) to enumerate every other path that references the legacy
   directory shape. Filter out matches inside the deletion target
   itself and inside any explicit history-pointer (e.g., a
   `CHANGELOG.md` entry that describes the deletion).
3. Delete pass: `git rm -r catalog/` removes the entire tree.
4. Scrub pass: for every reference found in step 2, either delete the
   reference (if the surrounding doc is wholly about the legacy
   structure) or update it to point at the new XML source of truth
   (`repo-specs/**/*-marketplace.xml`).
5. Documentation: log the deletion in `CHANGELOG.md` if the repo has
   one; otherwise capture it in the work-unit commit message.
6. Verify pass: re-run both audit commands; confirm zero results
   (modulo the CHANGELOG history pointer, which the verification
   command excludes via `--`-path filtering).

The story has exactly one task (S1-T1) because the work is one atomic
unit and splitting it would create a partial-delete intermediate state
where `git ls-files catalog/` returns zero but a stale README still
documents the deleted tree.
