## Description

Add JSON output to `kanon why`. Per spec Section 4.5 step 4, the `--format` flag supports both
`text` (default, from T1) and `json`. T4 extends the choices set from `("text",)` to
`("text", "json")` and adds the JSON formatter.

The JSON shape is a top-level array of chain objects. Each chain is a list of node objects, in the
same order as the text format prints them (top-level source first, target node last). Each node
object has exactly five keys:

```json
[
  [
    {"kind": "source",  "name": "<source-name>", "ref": "<ref-or-null>", "sha": "<sha>", "url": "<url-or-null>"},
    {"kind": "include", "name": "<xml-manifest-path>", "ref": "<ref>", "sha": "<sha>", "url": "<url>"},
    {"kind": "project", "name": "<project-name>", "ref": "<ref>", "sha": "<sha>", "url": "<url>"}
  ]
]
```

Field semantics:

- `kind` -- one of `source` (top-level `KANON_SOURCE_*` entry), `include` (transitive XML
  manifest), `project` (leaf repo). Drawn from the resolved-tree node type.
- `name` -- the human-readable identifier of the node (source name, manifest-relative XML path, or
  project name).
- `ref` -- the unresolved REVISION / branch / spec / tag for this node from `.kanon` or the XML
  manifest, before resolution. May be `null` when not applicable (e.g., a transitive include that
  was inherited without an explicit revision attribute).
- `sha` -- the resolved SHA (full 40-char hex; not truncated). For nodes resolved against a tag,
  this is the tag's commit SHA.
- `url` -- the canonicalized repo URL (via `core/url.py::canonicalize_repo_url`). May be `null`
  for nodes that do not have an associated URL (rare; `source` entries always have a URL because
  every `KANON_SOURCE_*_URL` is present by construction).

Other details:

- Output via `json.dumps(chains, sort_keys=False, indent=<constant>)` followed by `"\n"`. The
  indent constant `KANON_WHY_JSON_INDENT` (default 2) lives in `constants.py`.
- `--format json` selection mirrors T1: argparse choices extend to `("text", "json")`; CLI flag
  overrides `KANON_WHY_FORMAT` env var.
- Ambiguity errors (T2) and not-found errors (T3) emit to stderr in plain-text form regardless of
  `--format` (errors are not JSON-encoded; only the success-path chain output is).

Spec source: `spec/kanon-list-add-lock-features-spec.md` Section 4.5 step 4 (JSON shape) and
Section 7 flag table.
