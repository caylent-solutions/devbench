# E4-F1-S1: `kanon outdated` implementation

## Status: in-queue

## Description

Implement the `kanon outdated` command in four sequential tasks that share the same source file
(`src/kanon_cli/commands/outdated.py`) and the same test fixture structure under
`tests/unit/test_outdated*.py` + `tests/integration/test_outdated*.py`.

- **T1** lands the core command surface (subcommand registration, `.kanon` read, per-source row
  construction for tag-pinned sources, default `table` format via `KANON_OUTDATED_FORMAT`).
- **T2** adds branch-pinned-source column handling (12-char SHA truncation in both `latest-*`
  columns; `drift` upgrade-type when locked SHA differs from branch HEAD).
- **T3** adds the `--fail-on-upgrade` flag (exit 1 when any row reports an upgrade; default exit 0
  preserved per spec Section 0.2).
- **T4** adds the `--format json` output path (mirrors the table; one object per source).

T1 ships the command file end-to-end with the default behaviours; T2/T3/T4 each amend `outdated.py`
to add their respective flag handling. Each task pairs its source change with a dedicated
`tests/unit/test_outdated_<feature>.py` and a matching `tests/integration/test_outdated_<feature>.py`
so source/test atomicity is preserved (see `devbench/docs/source-test-atomicity.md`).

Spec source: `spec/kanon-list-add-lock-features-spec.md` Section 4.4 (behaviour 1-3, branch-pinned
paragraph), Section 0.2 (exit-code policy), Section 7 (`KANON_OUTDATED_FORMAT`, `--fail-on-upgrade`,
`--format`).
