## Description

This feature ensures that prior feedback from failed judges is reliably injected into every subsequent execution attempt in the orchestrator's retry loop. Prior feedback injection exists in `cli.py` for interactive mode but the spec identifies a risk that some retry paths in `orchestrator.py` may not consistently pass `previous_feedback` to `claude_executor.execute()`. The feature audits all retry branches, fixes any that miss feedback, and adds a regression test to prevent future regressions.

## Test Plan (Spec-Driven TDD)

### Contract Definition

The orchestrator's retry loop accumulates feedback from all prior failed judges and passes it in the `previous_feedback` argument to every subsequent `execute()` call. The first call may pass `previous_feedback=None` or an empty string; all subsequent calls must pass a non-empty feedback string.

### Acceptance Tests (BDD-style)

# AC-1 & AC-2: feedback injected on retry
Given a work unit whose first execution results in a failing CodeReviewJudge verdict
When the orchestrator retries the work unit
Then `execute()` is called with `previous_feedback` containing the CodeReviewJudge's feedback text

# AC-3: no retry with None feedback after first
Given a work unit that has failed twice
When the orchestrator attempts a third execution
Then `previous_feedback` is a non-empty string combining feedback from both prior failures
