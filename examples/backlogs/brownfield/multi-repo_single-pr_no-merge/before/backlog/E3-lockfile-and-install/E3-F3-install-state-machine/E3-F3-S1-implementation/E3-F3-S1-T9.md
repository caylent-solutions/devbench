# E3-F3-S1-T9: Concurrency lock extension to `kanon add` and `kanon remove`

## Status: in-queue

## Target Repository

## Description

Today's `kanon install` acquires an exclusive `fcntl.flock(LOCK_EX)` on
`.kanon-data/.kanon-install.lock` (`INSTALL_LOCK_FILENAME` in
`constants.py`) so concurrent install invocations serialise. Spec
Section 7.5 extends this lock to also cover:

- `kanon add` (E2-F4): mutates `.kanon`; the lock prevents a concurrent
  install from reading a half-written `.kanon` (atomic temp+rename
  prevents truncation but does not prevent racing readers from missing a
  source).
- `kanon remove` (E2-F5): also mutates `.kanon`; same rationale.
- `kanon doctor --refresh-completion-cache`: mutates completion-cache
  files; the lock prevents two concurrent refreshes from clobbering each
  other.

Same lock file (`.kanon-data/.kanon-install.lock`), same `fcntl.flock`
semantics: blocking exclusive, kernel-released on process exit (so
crashes do not leave a stuck lock).

If `.kanon-data/` does not yet exist (first invocation in a fresh
workspace), kanon creates it eagerly with `mkdir(parents=True,
exist_ok=True)` before acquiring the lock so the lock file has a place
to live.

Implementation surface:

- Extract today's install-only lock-acquire code into a reusable context
  manager at `src/kanon_cli/utils/concurrency.py` (new module). Public
  API: `kanon_workspace_lock(workspace_root: Path)` returns a context
  manager that creates `.kanon-data/` if absent, opens the lock file,
  acquires `LOCK_EX`, yields, and releases (and closes the FD) on
  context exit. The context manager is reentrant only across processes,
  not within a single process (the standard `fcntl.flock` semantics on
  Linux do not promote LOCK_EX to LOCK_SH if the same process reacquires;
  the wrapper documents this).
- Update `src/kanon_cli/core/install.py` to import and use
  `kanon_workspace_lock` instead of the inline `fcntl.flock` block; the
  behaviour is byte-equivalent.
- Update `src/kanon_cli/commands/add.py` (created by E2-F4-S1-T1) to wrap
  its `.kanon` mutation inside `kanon_workspace_lock`.
- Update `src/kanon_cli/commands/remove.py` (created by E2-F5-S1-T1) to
  wrap its `.kanon` mutation inside `kanon_workspace_lock`.
- Update the completion-cache refresh path in `src/kanon_cli/commands/doctor.py`
  (existing) to wrap its mutation inside `kanon_workspace_lock`.

Spec source: `spec/kanon-list-add-lock-features-spec.md` Section 7.5
(Concurrency and atomicity) including the extension of the lock to
`kanon add` / `kanon remove` / `kanon doctor --refresh-completion-cache`
and the eager-create rule for `.kanon-data/`.

### Approach

1. **TDD RED:** Author `tests/unit/test_concurrency.py` with
   parametrised cases: (a) `kanon_workspace_lock` creates `.kanon-data/`
   if absent; (b) lock acquire is exclusive (blocking) across processes;
   (c) lock release happens on normal context exit; (d) lock release
   happens on exception inside the context (try/finally semantics).
   Inter-process tests use `multiprocessing.Process` with a barrier so
   one process holds the lock while the other attempts acquisition with
   `fcntl.LOCK_NB` and verifies it fails until the first releases.
2. **TDD RED (integration):** Author
   `tests/integration/test_concurrency_serialization.py` spawning two
   concurrent `kanon install` subprocesses against the same workspace
   (using `subprocess.Popen`) and asserting they serialise via
   timestamps on the resulting lockfile (the second install starts
   AFTER the first finishes; the lockfile mtime sequence proves it).
3. **TDD GREEN:** Implement `kanon_workspace_lock` as a context manager
   using `contextlib.contextmanager` plus `fcntl.flock`. Move the
   existing install-time `flock` code into this helper. Update the four
   call sites (`install`, `add`, `remove`, `doctor`).
4. **TDD GREEN (eager-create):** The context manager runs
   `workspace_root.joinpath(".kanon-data").mkdir(parents=True, exist_ok=True)`
   before opening the lock file. The lock file path is built from
   `INSTALL_LOCK_FILENAME` in `constants.py`.
5. **TDD REFACTOR:** None expected; this is a relocate-and-reuse change.
6. **Docs:** Update `docs/architecture.md` with the concurrency model;
   update `docs/troubleshooting.md` with the "another kanon process is
   running" wait scenario.
7. **Verify:** Full suite.
