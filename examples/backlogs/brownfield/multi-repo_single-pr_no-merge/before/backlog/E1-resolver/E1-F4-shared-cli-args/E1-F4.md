# E1-F4: Shared CLI args module (`core/cli_args.py`)

## Status: in-queue

## Description

Move the canonical definition of the `--catalog-source` argparse flag
out of `src/kanon_cli/commands/bootstrap.py` and into a new shared
module `src/kanon_cli/core/cli_args.py`. Today, the flag is defined
inline on the `kanon bootstrap` argparse parser; spec Section 3
primitives table row 2 and Section 3.5 mandate that the canonical
definition must not live on the deprecating bootstrap shim because
every new command (`kanon list`, `kanon add`, `kanon remove`,
`kanon outdated`, `kanon why`, `kanon doctor`, `kanon catalog audit`)
needs to import and reuse the same flag definition. E6 (bootstrap
deprecation shim) also requires the flag definition to be elsewhere
before it can collapse the shim.

The shared module exposes a factory function:

```python
def add_catalog_source_arg(parser: argparse.ArgumentParser) -> None:
    """Add the --catalog-source flag to the given parser."""
```

`commands/bootstrap.py` is updated to import this factory and call it
in place of the inline `parser.add_argument('--catalog-source', ...)`
call. No user-visible behaviour changes: the help text, default value,
env-var coupling (`KANON_CATALOG_SOURCE`), and argparse `dest` are
identical to today's inline definition.

Spec source: `spec/kanon-list-add-lock-features-spec.md` Section 3
primitives table row 2 (CLI flag + env var for catalog source) and
Section 3.5 (Standards audit and tightening).
