# E12-F1: Delete legacy `catalog/` tree and scrub internal references

## Status: in-queue

## Target Repository

- **Repo:** `caylent/caylent-private-kanon`

## Description

Single feature under E12: perform the repo-wide `catalog/` deletion and
remove every internal-tooling reference to `catalog/<name>/` paths in
one coordinated change.

The deletion is bounded to the `catalog/` directory tree at the repo
root. It does NOT touch:

- `repo-specs/**/*-marketplace.xml` (the new source of truth, written
  by E11).
- `.github/workflows/` CI jobs added by E10 (the Phase-2 CI guard that
  fails the build if a new `catalog/<name>/` directory is added flips
  from "tolerate existing tree" to "hard error on any presence" once
  this delete lands; E10 owns the guard, E12 just makes the guard's
  post-Phase-2 mode reachable).
- Any other repo content (`README.md`, `docs/`, etc.) except for the
  reference-scrub step.

Reference scrub covers any path in the repo that names `catalog/<name>/`
or that documents the legacy directory shape as authoritative. The
executor enumerates references via `git grep -F 'catalog/'
caylent-private-kanon/` (run from the workspace root) and removes any
that survive Phase 1 (e.g., README sections describing how to author
an entry as a directory, helper scripts that walked `catalog/*/`).

There is a single child story; no parallelism is needed because the
deletion is one atomic commit on a single branch.
