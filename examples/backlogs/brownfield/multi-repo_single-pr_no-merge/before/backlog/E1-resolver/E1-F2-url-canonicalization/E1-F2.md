# E1-F2: URL canonicalization helper (`core/url.py`)

## Status: in-queue

## Description

New module `src/kanon_cli/core/url.py` exposing
`canonicalize_repo_url(url: str) -> str`. Returns a canonical string
form for the input git URL so equivalent URLs become byte-identical and
downstream callers can compare them with `==`.

Normalisations:

- Lowercase the host.
- Normalise scheme equivalents (`git@host:org/repo` <-> `ssh://git@host/org/repo` <-> `https://host/org/repo`).
- Strip trailing `/`.
- Strip trailing `.git`.
- Strip embedded user-info (`https://user@host/repo` -> `https://host/repo`).
- Preserve path case (some hosts treat paths case-sensitively).
- Reject URLs that carry query strings or fragments (canonical form is
  undefined for those; raise `ValueError` naming the offending input).

Used by:

- Conflict detection (Section 4.7 -- two sources pointing at the same
  repo with different URL spellings).
- `kanon why` URL matching (Section 4.5).
- Lockfile `canonical_url` field (Section 5).

Spec source: `spec/kanon-list-add-lock-features-spec.md` Section 4.0
"Repo URL canonicalization" subsection.
