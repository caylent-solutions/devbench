# E10-F2: Caylent-private-kanon CI guards

## Status: in-queue

## Description

GitHub Actions workflows that enforce the catalog-entry contract on every
PR + push to main in the `caylent/caylent-private-kanon` repo. Five
guards from spec Section 9a, packaged into three workflow tasks:

- **T1 -- `.github/workflows/audit.yml`** runs three checks:
  1. `kanon catalog audit .` against the repo root (initially without
     `--strict` -- the deprecation window for legacy `catalog/`
     warnings is still open; promoted to `--strict` after the E12
     Phase 2 migration completes).
  2. `kanon validate xml`, `kanon validate marketplace`, AND `kanon
     validate metadata` (the new sub-subcommand from E5-F3).
  3. Smoke test: install latest kanon CLI, run `kanon list
     --catalog-source <this-repo-at-HEAD>`, assert the returned
     entries match exactly the set produced by `git ls-files
     repo-specs/**/*-marketplace.xml`. No silent skips, no orphans.
- **T2 -- `.github/workflows/no-catalog-dir.yml`** fails the build if a
  PR introduces any new `catalog/<name>/` path. Implementation: `git
  diff --name-only origin/main..HEAD` filtered against
  `^catalog/[^/]+/`; non-empty match fails. Before E12 Phase 2
  completes, the guard tolerates the existing tree but errors on NEW
  entries.
- **T3 -- `.github/workflows/pep440-tags.yml`** validates that any tag
  pushed to the repo (or referenced by a PR) has a last-path-component
  that is a valid PEP 440 version. Implementation: inline `python -c
  "from packaging.version import Version; Version('<tag>')"` or a small
  helper. Warns initially per spec Section 9a / Section 15; future
  release promotes to hard error.

Every task in this feature is YAML-tier: no Python source authored, so
the Python-tooling AC-FINAL entries carry the canonical N/A suffix.

Spec source: `spec/kanon-list-add-lock-features-spec.md` Section 9a (CI
subsection bullets 1-5).
