# E3-F3-S1: Implement the install state machine and supporting flags

## Status: in-queue

## Description

Story covering the nine tasks that together ship the `kanon install`
lockfile state machine end-to-end. The tasks form a small DAG:

- T1 is the foundation: it modifies `core/install.py::install` to read the
  lockfile, compare `kanon_hash`, and branch on the five-row state matrix
  (absent / consistent / hash-mismatch / dangling-SHA / catalog-mismatch).
  Every other task in the story depends on T1.
- T2 (`--refresh-lock`), T3 (`--refresh-lock-source`), T4
  (`--strict-lock` + `--strict-drift`), T5 (canonical-URL conflict
  detection at the `<project>` level), T6 (`<include>` cycle + diamond),
  T7 (default `--lock-file` derivation), T8 (HTTPS enforcement) all depend
  on T1 but can run in parallel relative to one another.
- T9 (concurrency-lock extension) depends on T1 plus E2-F4 / E2-F5
  (`kanon add` / `kanon remove` command surfaces) because it wires the
  lock into those entry points.

Spec source: `spec/kanon-list-add-lock-features-spec.md` Section 4.7
(state matrix and flags), Section 4.7.1 (install engine contract),
Section 7.5 (concurrency lock extension), Section 3.6 (trust model
prohibition on insecure remotes).
