# E3-F3-S1-T8: HTTPS enforcement for `<remote>` URLs in resolved manifests

## Status: in-queue

## Target Repository

## Description

Implement the spec Section 4.7 "`<remote>` non-HTTPS URL" rule together
with the Section 3.6 trust-model requirement: when a resolved manifest
XML contains a `<remote>` element whose `fetch` URL is not HTTPS or SSH,
`kanon install` raises a hard error unless the
`KANON_ALLOW_INSECURE_REMOTES=1` env var is set.

The accept set:

- HTTPS (`https://...`): allowed unconditionally.
- SSH (`git@host:org/repo.git` OR `ssh://...`): allowed unconditionally.
- HTTP (`http://...`): rejected by default; allowed only with
  `KANON_ALLOW_INSECURE_REMOTES=1`.
- `file://`: rejected by default; allowed only with
  `KANON_ALLOW_INSECURE_REMOTES=1`.
- Any other scheme (`git://`, `ftp://`, custom schemes): rejected by
  default; allowed only with `KANON_ALLOW_INSECURE_REMOTES=1`.

The check runs after manifest XML parsing and before any clone or
`git ls-remote` attempt for any `<project>` whose `<remote>` resolves
to a non-HTTPS/SSH URL. Failure raises `InsecureRemoteUrlError` listing
the source path, the offending `<remote>` name, the URL, and the
remediation: "Use an HTTPS or SSH `<remote>` URL, or set
`KANON_ALLOW_INSECURE_REMOTES=1` if this is intentional (the override
disables the security check)."

Implementation surface:

- Add `KANON_ALLOW_INSECURE_REMOTES = "KANON_ALLOW_INSECURE_REMOTES"` to
  `src/kanon_cli/constants.py` (the env-var name).
- Add `_classify_remote_url_scheme(url: str) -> RemoteUrlScheme` helper
  in a new module `src/kanon_cli/core/remote_url.py`. Enum values:
  `HTTPS`, `SSH_GIT_AT`, `SSH_PROTOCOL`, `HTTP`, `FILE`, `OTHER`.
- Add `_enforce_remote_url_policy(url: str, allow_insecure: bool) ->
  None` helper that raises `InsecureRemoteUrlError` for HTTP / FILE /
  OTHER schemes when `allow_insecure=False`. Returns `None` on accept.
- Add `InsecureRemoteUrlError(InstallError)` exception class.
- Wire the check into the resolver path in `core/install.py`: for each
  resolved `<remote>` URL encountered during transitive include walks,
  call `_enforce_remote_url_policy(url, allow_insecure=os.environ.get(KANON_ALLOW_INSECURE_REMOTES) == "1")`.

The check is enforced on every resolution path (absent-lockfile fresh
resolve, refresh-lock, refresh-lock-source). On the lockfile-consistent
replay path, the check is ALSO enforced against the locked URLs because a
malicious lockfile could record an HTTP `<remote>` URL that the operator
should not silently clone.

Spec source: `spec/kanon-list-add-lock-features-spec.md` Section 4.7
"`<remote>` non-HTTPS URL" row; Section 3.6 (Trust model) HTTPS
requirement.

   parametrising every scheme + env-var combination: HTTPS allowed
